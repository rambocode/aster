# 增量事务 v1

客户端必须协商 `terminal_delta_v1`，同时支持 `snapshot_transaction_v1`。不支持增量事务的旧 probe 在握手阶段拒绝，不能把增量当作完整快照解析。

完整事务头：

```json
{"type":"snapshot_begin","length":123,"sha256":"<64 hex>","sequence":10,"baseSequence":null}
```

增量事务头：

```json
{"type":"delta_begin","length":20,"sha256":"<64 hex>","sequence":12,"baseSequence":10}
```

数据继续使用 kind-2 的索引分块。完整事务以 `snapshot_end` 结束，增量以 `delta_end` 结束；结束类型必须与开始类型一致。长度、索引和 SHA-256 全部通过后才能应用。

`sequence` 是源 PTY 输出代次。一个事务可以包含多个读取块，因此不要求 sequence 每次只加一；增量必须明确覆盖当前已应用的 `baseSequence`，且新 sequence 大于 base。完整快照可在相同代次刷新布局/尺寸，但不能倒退。

服务端只在起止均处于 VT ground 状态、UTF-8 边界可靠且全部序列允许镜像时发送原始增量。查询、窗口操作、敏感 OSC、图像字符串和未知/分片序列通过生成的快照同步。分类器持续跟踪被快照替代的序列，避免后续字符串片段被误当成普通文字。

桥接端独立检查增量安全性，直接拒绝危险增量。正常增量写入既有 VT，不执行重置；完整快照承担必要的重新建屏。

基准不匹配时，客户端：

1. 发送一次 `snapshot` 请求并停止向远端转发输入。
2. 排空并丢弃失配增量，保留最后完整画面。
3. 丢弃此期间的键入和未完成前缀键状态。
4. 收到通过校验的新完整快照后恢复输入和增量应用。

错误开始/结束顺序、超限、损坏、过早增量和不安全增量均不能进入本地终端。关闭桥接连接不结束服务端任务。
