受管模式必须同时提供两个环境变量，缺一即完全不介入，App 保持既有本地终端行为：

```sh
ASTER_SESSION_BINARY=<绝对路径>/SessionRuntime/zig-out/bin/aster-session
ASTER_SESSION_STATE_DIR=<已存在且仅当前用户可访问的私有父目录>
```

## 6. 待确认（按默认假设推进，未阻塞）

1. **受管模式的开关形态。** 规格只要求「只向专用测试配置开放」，未规定开关放在配置文件还是环境变量。默认假设：用环境变量（`ASTER_SESSION_BINARY` + `ASTER_SESSION_STATE_DIR`）开启，不进入设置界面，也不写入 `AsterConfiguration`；P8 切默认托管时再定型。
2. **会话客户端的代码归属。** 设计草案 §3.1 说 AsterCore 承载「纯值类型和状态转换」。本实现把会话客户端协议、纯解码层与 `LocalManagedSessionClient` 一起放在 AsterCore，理由是 `aster-cli` 与 App 必须共用同一套动作语义而不复制服务端领域逻辑（§3.1 同段要求）。`Sources/Aster/Remote/` 仍只承载 App 侧编排与投影。
3. **本地后台实现的传输面。** 采用 P1 已交付的 `aster-session` 结构化 CLI 作为本机传输，而不是在 Swift 内重新实现协议分帧。`TerminalSession` 只看到「引用 + 桥命令」，未嵌入服务协议（P2.2 的原文要求）。P3 的 SSH 传输会引入长连接客户端，届时同一 `ManagedSessionClient` 接口可换实现。
4. **`detached` 是否应进入协议层状态枚举。** 客户端分离是客户端事实，服务端仍视该终端为 running。默认假设：`ManagedTerminalState`（服务端真值）不含 `detached`；客户端在 `TerminalSessionLifecycleState` 与 CLI 结果里单独表达 `detached`，本地态优先于服务端上报。
