## 控制连接的真实 socket 收发

- 新增 service_connection.zig，接管已通过同用户鉴权的非阻塞 stream，先排入 Hello，再按既有有界帧协议解析请求并调用真实健康处理器。连接仅在调用期间借用控制上下文，移动连接不会留下内部悬空指针。
- 每轮最多读取 16 KiB、写出 64 KiB；待发送内容最多两个最大控制帧（2 MiB + 两个帧头）。发送不足时保留偏移，背压返回连接级 SlowConsumer，不阻塞其它连接。
- 半关闭写端后仍排空已生成的回复；EOF 核对残缺帧。非控制帧、解析错误及发送失败将连接标为失败，后续 tick 拒绝恢复使用，调用方必须释放连接。
- 发送使用 MSG_NOSIGNAL，无需依赖整个进程忽略 SIGPIPE。真实子进程恢复 SIGPIPE 默认处置并关闭独占对端，写入失败仍可正常退出。

## P1.1 后台启动闭环

- 新增 service_launch.zig 和平台 daemon.c，实现 `server start <private-parent> <name>`。父进程先验证路径，再创建私有报告通道并 fork；子进程 setsid，重定向 0/1/2 到 /dev/null，保留状态父目录与报告 FD，关闭全部其它继承 FD。
- macOS 用 proc_pidinfo 枚举本进程 FD；Linux 用 /proc/self/fd 先收集再关闭实际描述符，不按最大编号遍历。Linux 首次实测暴露 musl strtol 对点目录设置 errno 的差异，已分离 readdir 错误判断并跳过非数字项；失败记录未计为通过。
- 启动器恢复自身 SIGCHLD 默认处置，避免调用方忽略 SIGCHLD 时临时子进程被自动回收而破坏 waitpid。此接口只用于单线程、随后退出的 CLI 启动器。
- 本次启动 epoch 由父进程生成并传入子服务，在创建控制上下文前采用。收到 ready 后还要通过真实 status 查询核对该 epoch，不能把替代实例错误关联到启动 PID。已有锁 owner 则返回 already_running，并等其真实状态可查。
- 启动查询有总期限；超时返回 StartupOutcomeUnknown，不重启、不替换、不杀 PID。身份损坏返回 ServiceInitializationFailed 并保留文件。CLI 成功输出 server_start JSON，包含 started/already_running 与已校验状态；已有实例不猜测 PID。
