## 1. 开启方式

远端受管模式在 P2 的两个开关之上再加一个，三者齐备才走 SSH 传输：

```sh
ASTER_REMOTE_SSH_TARGET=<原始 SSH target，例如 root@ubuntu@orb>
ASTER_SESSION_BINARY=<远端 aster-session 的绝对路径>
ASTER_SESSION_STATE_DIR=<远端私有状态父目录>
ASTER_SESSION_NAME=<命名会话，缺省 default>
```

`ASTER_REMOTE_SSH_TARGET` 缺失或解析失败时保持 P2 的本机传输，不做隐式远端化。
另有两个连接设置（不进入凭据存储）：

- `ASTER_REMOTE_MANAGE_SSH_CONFIG=0|false|no` —— 关闭私有临时 SSH 配置与 ControlMaster 管理，直接使用用户 OpenSSH 配置。
- `ASTER_REMOTE_BINARY` —— 指定本地自定义服务产物；安装前同样做平台/协议/摘要校验，且必须显式接受「开发产物」。

验收开关（默认关闭，避免普通测试触碰远端机器）：`ASTER_P3_ORB=1`、`ASTER_P3_TARGET`、`ASTER_P3_RUN_ID`、`ASTER_P3_LOCAL_BINARY`。

### 3.2 A10：SSH target 与认证 —— 通过

- **target 形式。** alias、`user@host`、`ssh://user@host:port`、IPv6（URI 形式 `ssh://[2001:db8::1]:22`、非 URI 形式裸 `::1`）、以及真实 `root@ubuntu@orb` 均按 OpenSSH 语义解析（`RemoteSSHTargetTests`，18 用例）。`ssh://host` 不臆测端口 22。真实连接见 §3.5。
- **不做本地 Shell 二次解释。** argv 直接交给 `/usr/bin/ssh`，target 以 `--` 隔离且元素与原文逐字节相同；远端命令逐参数 POSIX 单引号转义后合成**一个** argv 元素。argv 中不出现 `StrictHostKeyChecking=accept-new|no`。
- **非法输入连接前拒绝。** 采用**允许字符表**而不是禁止表（字母数字与 `.-_@:%`，`/` 与方括号只在 `ssh://` URI 形式里合法），任何未列出的字符直接拒绝，新增 Shell 元字符不会因漏列放行。非 URI 形式的方括号 IPv6（`[::1]`）同样在连接前拒绝，因为 OpenSSH 只在 URI 里理解方括号。
- **后台非交互。** `BatchMode=yes` + stdin 接 `/dev/null`：认证需要交互时立即失败并归类，不会挂起。
- **脱敏。** `RemoteSSHDiagnostics.redact` 只保留白名单标记，实测输入含 `/Users/x/.ssh/id_ed25519` 与 `Enter passphrase for key` 时输出不含这些原文。
- **attention。** `RemoteSSHFailureKind.requiresExplicitSetup` 把认证/主机密钥/远端命令缺失归入需要显式处理，网络类归入可自动退避。

## 5. 本轮修复的真实缺陷

### 5.1 `server stop` 在有运行中终端时误报失败（SessionRuntime）

- **是什么。** `SessionRuntime/src/service_client.zig::waitStopped` 在收到 stop 确认后，只要连接上再读到**任何**字节就返回 `error.InvalidServiceStop`。但设计草案 §5 明确要求服务进入 stopping 后「最多尝试 250ms 排空已生成回复」，这些字节是合法的。结果是：只要该会话还有运行中的终端，`server stop` 必然输出 `{"code":"InvalidServiceStop"}` 并以 exit 1 结束——而服务其实已经正常停止、进程也已回收。
- **影响。** 脚本化停止拿到的退出码不可信，会诱使调用方重试或升级成信号；P3 的清理路径直接受影响。macOS 与 Linux 两个构建都能复现。
- **修复位置。** `waitStopped` 改为丢弃这些字节并继续等待连接关闭，上界仍由既有 deadline 兜底。
- **红/绿证据。** 修复前：会话内有一个运行中终端时 `server stop` exit 1；修复后同一场景 exit 0、返回 `state=stopped`，任务 PID 立即 `GONE`。`tests/service_stop.py` 的 `invalid_ack` 用例（针对另一处 `stopping=false` 的拒绝）仍然通过。

### 5.2 `service_server.py` 能力断言过期（SessionRuntime 测试）

服务自 P1 起就广播 `surface_interest`，但 `tests/service_server.py:49` 的集合断言没跟上，导致该套件在本轮之前就无法通过。已把 `surface_interest` 补进期望集合。这是陈旧断言，不是行为变更。

### 5.3 `RemoteProbeReport.preferredCandidate` 恒返回 nil

`RemoteHostProbe.parse` 只能从 `--version` 得到协议版本，能力集合恒为空；原实现却用 `RemoteCompatibilityCheck.evaluate` 判定，于是每个候选都因「必需能力缺失」被排除。改为只按协议主版本筛选，并在注释里写明最终兼容判定发生在握手之后。该属性此前无调用方，未造成线上行为差异。

### 5.4 异步化后的宿主测试夹具竞态

`ManagedTerminalBinder.bind` 改异步后，`Tests/AsterTests/ManagedTerminalAppLifecycleTests.swift` 的三处断言变成竞态：新建 Pane / 重开 App 的绑定尚未完成就被断言；`ControlTestWorkspace` 自动创建的受管终端会在用例显式 `bindManagedTerminal` **之后**覆盖引用，导致 `session.end` 结束了错误的终端。已在这三处补等待，并把自动创建的终端先结束掉。断言本身未放宽。

## 6. 未执行 / 未完成项

1. **只有 OrbStack x86_64 Linux 的远端证据。** macOS 远端服务、arm64 Linux、非 root 普通用户都未验证。A10/A11/A12 的通过范围仅限该组合，四平台矩阵按 P8 处理。
2. **签名验证是注入点，尚无真实签名链。** `RemoteInstallTransaction` 的 `signatureVerifier` 是可注入闭包，本阶段用测试产物（`testArtifact`，允许无签名）跑通全流程。受管发行的真实签名/验签属于 P8.2 的 release manifest 工作。
3. **人工 GUI 验收未执行。** P3.7 的边界与提示由真实代码路径（`TerminalTargetOpenCoordinator.open`、`TerminalSession.noteManagedCapabilityLimitation`）与单测覆盖，但没有人工点击菜单、截图或录屏。stages.md「UI 阶段使用独立配置和专用测试窗口实际操作」在此保留为未完成项。
4. **远端受管终端的显示桥未在真实 App 实例里端到端跑过。** `bridgeExecutablePath`/`bridgeArguments` 的远端形态（`ssh -tt … terminal attach`）有单测覆盖，OrbStack 上也验证了 `terminal attach` 本身可用（P1 证据），但「真实 Ghostty surface → ssh → 远端受管终端」这条完整链路本阶段没有在运行中的 App 上执行。它依赖 P4 的机器侧栏才能被用户触发；本阶段不启动用户的 `/Applications/Aster.app`，也没有为此单独组装隔离 bundle。
5. **关闭路径仍是同步服务调用。** `TerminalSession.stop()` 的结束分支与 `terminateManagedTerminal` 必须在 App 终止前完成，保留同步调用并靠客户端超时兜底（远端 20 秒）。极端网络条件下退出会被拖慢。若 P4 引入长连接客户端，应改为「先发出停止请求、再有界等待」。
6. **URI 形式的 IPv6 无法真实连通。** 本机 OpenSSH 10.3p1 不接受 `ssh://` 里的 IPv6 字面量（带不带方括号都打印 usage 并退出），因此 `ssh://[2001:db8::1]:22` 只做解析验证；真实 IPv6 连通性用非 URI 形式 `root@ubuntu@::1` 证明（见 §3.5）。这不是 Aster 的逻辑缺陷，但解析层放行了一种传输层不可能兑现的写法，是否在 P4 直接拒绝待定（见 §7.6）。
7. **慢消费者、断线退避、健康检查**属于 P4.4/P4.6，本阶段未实现也未验证。
8. **测试目录未清理。** 远端 `~/.local/state/aster-test/` 下保留了本轮 runID 目录与 P0/P1 时期的历史目录，便于复验；没有自动清理策略。

## 7. 待确认（按默认假设推进，未阻塞）

1. **必需能力集合与设计草案不一致。** 草案 §5 把 `session_snapshot` 列为必需能力，但当前服务不广播它（`service_server.zig` 广播 `health_check / server_lifecycle / terminal_control / terminal_observe / surface_interest`），运行时自己的附加契约（`terminal_attach.zig::negotiateRequired`）要求的也只是 `terminal_control / surface_interest / health_check`。**默认假设**：P3 的必需集合取运行时附加契约的三项，`session_snapshot` 降为可选；它是共享工作区结构（P4.2）才使用的能力，P4 接入时再加入必需集合。若不这样处理，P3 会把可用服务误判成不兼容。
2. **远端受管模式的开关形态。** 沿用 P2 的默认假设（环境变量，不进入设置界面）。`ASTER_REMOTE_SSH_TARGET` 是新增的第三个开关；机器配置的持久化形态与设置界面留给 P4.3/P4.5。
3. **安装根目录。** 默认 `<home>/.local/share/aster`（`versions/<version>/aster-session` + `bin/aster-session` symlink）。验收使用隔离的 `<runRoot>/install`，不触碰默认位置。若后续要与包管理器安装共存，需要在 P8.2 定型目录约定。
4. **`developmentBuild` 的「显式接受」入口。** 当前是 `RemoteInstallTransaction(acceptDevelopmentArtifact:)` 参数，由调用方（设置流程）提供。P3 没有设置界面，验收里由用例显式传入。P4.3 加入机器设置后应把它做成一次明确的用户确认。
5. **非 URI 的方括号 IPv6 已改为连接前拒绝。** `root@ubuntu@[::1]` 解析能通过，但 `rawText` 才是进 argv 的字段，OpenSSH 必然报 `Could not resolve hostname [::1]`。这违反「注定失败的形式在连接前拒绝」的规则，已改为拒绝，裸 `::1` 仍合法。**默认假设**：`ssh://[IPv6]:port` 保持可解析（RFC 形式正确，且未来的 OpenSSH 或替代传输可能支持），只在文档里标注当前 OpenSSH 不支持；若 P4 决定收紧，改为一并拒绝。
6. **`RemoteWorkspaceBoundary` 的动作清单。** 目前列了 5 类本机动作（File Pane、打开本机路径、访达显示、路径补全、拖入本机文件）。远端 Pane 的完整动作面要等 P4 共享工作区落地后才能穷举；届时新增动作必须同步加入该枚举，否则会默认放行。
