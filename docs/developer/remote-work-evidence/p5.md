## 0. 开启方式

P5 建立在 P4 的远端受管模式之上。Agent 状态操作通过现有的 SSH 传输 + 控制协议执行：

- `agent list <state-parent> <name>` 列出会话中所有 Agent 的状态
- `agent report <state-parent> <name>` (stdin JSON) 上报 Agent 状态变更
- `agent explain <state-parent> <name> <terminalID>` 获取 Agent 详情与诊断
- `agent ack <state-parent> <name> <terminalID>` 确认 Agent 完成通知

新增能力 `agent_state`，服务启动后在握手中广播。

## 11. A16.2 显示桥 bug 修复与真实 grok 验证（v4）

### 11.1 根因与修复

**现象：** 远端受管终端启动 grok（crossterm/ratatui TUI）后，本机显示桥 1–2 秒内退出，isProcessRunning=false，lifecycleState=detached，读屏全空。

**根因 1 — 服务端 UnsupportedProjection：** `surface_service.zig::tick` 每轮调用 `checkGeometry`，TUI 发送 RIS (\x1bc) 后终端像素状态可能短暂偏移，`checkGeometry` 返回 `error.UnsupportedProjection`，`tick` 把它当作不可恢复错误 → 断开 surface 连接 → 桥读到 EOF 退出。

**修复 1：** `surface_service.zig::tick`：对 `UnsupportedProjection` 容错，记日志跳过当前 tick，不断开 surface。桥的 resize 机制会在下一次循环恢复对齐。

**根因 2 — 客户端 eventStreamSubscribed 竞态：** 事件订阅握手在首次 `synchronize()` 完成之前到达，此时 `controller.revision == 0`，几乎任何非零 revision 都触发第二次 `refresh`，可能在首次 `apply` 之前重建画面兴趣集合。

**修复 2：** `RemoteWorkspaceCoordinator.eventStreamSubscribed`：当 `controller.projection == nil`（首次 apply 尚未完成）时跳过补快照，让初始 refresh 独占首轮同步。

- `SessionRuntime/src/surface_service.zig` — tick 容错 UnsupportedProjection

本节由主 agent 接手完成。第 12 节（v5）的"通过"不算数：桥在 grok 启动后仍会退出一次靠 reattach 掩盖，blocked/complete/exit 检不出，且测试在每一步都用 `agent.report` RPC 注入状态、远端装的是只写日志的假 hook。以下按缺口记录。

### 13.1 缺口 2：显示桥在 grok 启动后退出一次

- **实测排除**：P4 显示桥用例（远端普通 shell）在最终二进制上桥全程存活（`.build/remote-work-evidence/p5-gap2-bridge-probe.log`，PID 91213 从 (a) 到 (d) 不变，仅 (e) 主动分离），所以不是协调器竞态。
- **真实根因**：`service_server.zig` 把 `agent.changed`（以及 P4 的 `workspace/tab/pane.changed`）广播给**所有**控制连接，包括 `terminal attach` 的桥；`terminal_attach.zig::Client.event` 对 `terminal.exited`/`lease.revoked` 之外的事件种类一律返回 `UnexpectedControlEvent`，桥以退出码 1 结束。任何一次 agent 状态上报都会杀掉所有已附加的显示桥；上一位 agent 的"启动后 detach 一次"正是测试的 `agent.report` bootstrap 触发的。桥的 stderr 打在 surface 上随即被销毁，所以此前看不到原因。
- **修复**：桥对外来广播只校验信封并推进 `event_sequence/event_revision`，不退出（`isTerminalControlEvent`）。同时新增 `<state>/<name>/attach-exits.log`（0600，1 MiB 封顶）记录桥的拒绝码与退出原因，App 侧 `TerminalSession.lastManagedBridgeExit` 保留桥退出瞬间的退出码与画面尾部并写入 `terminal.managed_bridge_exited` 诊断。
- **红/绿**：新增 `SessionRuntime/tests/bridge_foreign_events.py`。旧二进制（修复前 `zig-out`）：`bridge exited on agent.changed broadcast: rc=1`；新二进制：桥存活、继续收发、之后的租约撤销仍按序处理并以 1 退出。v7/v10 真实 grok 运行中桥不再 detach（v10 `步骤1: 桥稳定=true`，无 "已 detached"）。
- 附带清理：删除三处写 `/tmp/aster-bridge-exit-diag.log` 的临时调试代码。

### 13.2 缺口 1：blocked / complete / exit 检不出

- **根因 A（客户端权威设计错配）**：`applyRemoteAgentState` 收到任何远端上报就 `stopAgentScreenMonitor()`。grok 的 hook 只有 SessionStart/PreToolUse/PostToolUse/SessionEnd，没有权限请求与 Stop 事件，于是"等待批准"与"回到空闲"永远检不出。本地终端早有正确规则（`syncAgentScreenMonitor`：只有 `fullLifecycleHooks` 的 provider 才停扫屏），远端实现没有照此。
  修复：`RemoteAgentStateAuthority.resolve` 与本地规则对齐——`fullLifecycleHooks`（openCode/pi/omp/kimiCode）→ hook 权威；有屏幕清单的部分 hook provider（Claude Code、Codex、Grok Build）→ 屏幕权威，hook 只负责识别 provider、绑定原生会话、提供工作证据；没有画面（隐藏/分离）时才退回 hook 状态。`applyRemoteAgentState` 改为与本地 `handleAgentTerminalDirective` 相同的关联规则并调用 `syncAgentScreenMonitor()`。
- **根因 B（hook 事件根本到不了客户端）**：Aster 的 hook 脚本把 OSC 6974 写到 Agent 的 tty；Ghostty VT 丢弃未知 OSC，显示桥重放的是**画面状态**而非原始字节，所以远端 hook 的 OSC 永远过不了桥，隐藏 Pane 更无从得知。此前几轮把"hook 到达"写成通过，靠的是 RPC 注入。
  修复：服务端 `session.zig` 在 PTY 输出里扫描 `ESC ] 6974 ; … (BEL|ST)`（跨块携带、256 字节上限、垃圾前缀后能重新同步、控制字节拒绝），`terminal_service.zig::applyAgentDirective` 把 `AgentState/Provider/SessionID` 映射为 agent_store 的 hook 来源记录并广播 `agent.changed`。`agent.explain` 因而显示 `source = hook`、`nativeSession` 为 grok 真实会话 ID。
  红/绿：新增 `SessionRuntime/tests/agent_hook_directive.py`（同一终端里三条指令：完整、跨两次写入拆分、垃圾前缀后再来一条；旧二进制 `deadline waiting for hook directive recorded as working`，新二进制通过并收到三条 `agent.changed`）。
- **Grok 原生 hook 的真实安装**：驱动脚本 v10 把 `Resources/agent-integration/aster-agent-hook.sh` 上传到远端，按 `AgentSetupService.generatedGrokTOMLBlock` 相同的命令格式（`/bin/sh '<script>' <state> grokBuild`）写入 `~/.grok/config.toml`，结束后恢复原文件。hook 脚本在 Linux 上按原样工作（`/dev/tty` 或沿父进程链找到 `/dev/pts/N`）。
- **测试去注入**：`RemoteWorkP5GrokAppTests` 删除全部 `agent.report` 注入与该辅助函数；每一步只等待产品自己得出的 `agentTaskState`。
