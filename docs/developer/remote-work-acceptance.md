# 远程工作模式验收规格

状态：A01–A03 的 P0 范围已通过，证据见 [P0 记录](remote-work-evidence/p0.md)。A04–A07 的 P1 范围已通过（A06 布局并发项按阶段归属移至 A15）；A08、A09 的 P2 范围已通过，证据见 [P2 记录](remote-work-evidence/p2.md)，其中 CLI→App 端到端已执行并通过，人工 GUI 一项保留为未执行；A10–A24 尚未执行；A01 的四平台最终矩阵仍在 P8 验收，不能将 P0 通过视为完整远程模式交付。

目标合同见 [设计草案](remote-work.md)，阶段入口与任务见 [分阶段实施](remote-work-stages.md)。表中“通过”必须同时满足全部断言；环境缺失、测试跳过和结果未知均不能计为通过。

## 1. 测试环境与证据规则

使用独立 Aster 配置、测试窗口和远端测试目录。默认目标为 `root@ubuntu@orb`；测试前重新记录 OS、架构、SSH 解析结果、二进制版本/摘要、协议和 capability。无需在 OrbStack 安装 Swift/Zig，运行本地或 CI 构建的目标产物。

每轮生成唯一 runID，目录放在远端 `${HOME}/.local/state/aster-test/<runID>`，服务/socket/manifest 指向该目录。所有停止、断连、磁盘故障和清理动作限定本次 runID，禁止按模糊进程名结束其他会话。测试 root 场景不能代替普通用户权限测试；最终矩阵增加非 root 用户。

测试任务由服务创建，持续输出递增序号与时间并写入本次目录；记录 serverID、epoch、sessionID、paneID、terminalID、PID 和操作前后的序号。仅看到相同标题不构成原进程存活证据。

每条记录包含：测试 ID、需求 ID、平台/架构、日期、代码 commit、前置状态、实际操作、预期/实际结果、退出码及证据路径。UI 证据包含截图或短录屏；输出不包含凭据和用户命令正文。性能结果记录机器规格、样本数、负载和测量方法。

## 2. 核心用例

### A01：平台与构建独立性（P0；R16）

1. 在干净构建目录生成 host macOS 与 Linux x86_64 的 `aster-session`。
2. 检查运行时依赖，确认 headless 不链接 AppKit、Metal、Sparkle 或应用资源路径。
3. 在 OrbStack 运行 `--version`、服务启动和 PTY 创建；记录与 Mac 不同平台的实际结果。

通过：目标产物独立启动且能收发 PTY 数据。P8 把同一用例扩展至全部四种服务平台组合。

### A02：协议和跨语言一致性（P0；R02/R12/R17）

1. Swift/Zig 分别读写同一 fixtures，覆盖有效消息、未知可选字段、必需字段缺失及错误响应。
2. 把帧拆成单字节读取、合并多帧读取，注入非法长度、超大载荷、截断 JSON 和错误 sequence。
3. 测试主版本不兼容、次版本差异、必需能力缺失和可选能力缺失。

通过：两端得到相同对象/错误；无越界、无无限等待；版本差异按能力处理；可选能力缺失不破坏已有终端。

### A03：VT 与 Ghostty 显示桥（P0；R02/R12）

1. 输入跨块 UTF-8、中文宽字符、emoji/组合字符、24 位色、OSC 8 链接、光标移动和擦除。
2. 运行使用备用屏幕和鼠标的真实 TUI，切换 bracketed paste、焦点报告和键盘模式。
3. 执行终端查询，记录服务端应答；改变尺寸，再重建本地 surface 并恢复快照。
4. 显示 Aster 当前支持的终端图形，验证重新附加后的图像位置与缓存资源。

通过：可见屏幕、光标和输入模式恢复一致，无重复应答或输入；备用屏幕退出后主屏幕正确。不能用原始输出尾部凑出近似画面。

### A04：分离保活（P1；R01/R02）

1. 创建持续计数任务，记录身份与 PID；断开客户端 30 秒后重新附加。
2. 循环 20 次，至少一次终止测试 bridge 进程，至少一次中断其 SSH 连接。
3. 在无人订阅时查询远端进程和输出文件。

通过：server epoch、terminalID、PID 不变，输出持续增长，重新附加显示最新状态；没有新建同命令任务。

### A05：单写者与接管（P1；R12）

1. A 客户端取得写权，B 只读观察；B 发送 input/resize 应失败。
2. B 显式接管；A 用旧 leaseEpoch 发送 input/resize。
3. 使用同一 `expectedLeaseEpoch` 同时发出两个接管请求，验证只有一个成功；覆盖初始空闲 epoch 0、释放后最后代数和旧代拒绝。断开新所有者，验证立即释放；另行保持连接但停止写活性，验证 15 秒失效。

通过：任何时刻只有一个有效写者，旧写者收到 `lease_lost`，只读观察不改变尺寸；失效后新连接可重新申请租约。

### A06：幂等、并发与故障（P1；R04）

1. 同一创建 requestID 发送两次，并在第一次执行后丢弃响应。
2. 重启服务后查询已提交结果；在日志事务和进程创建边界注入故障，核实未确认状态。
3. 重复结束请求，发送超出重试窗口的请求。

布局 revision 并发验收归入 A15，在 P4.2 实施布局事务后验收，要求不变。

通过：同 epoch 内不重复创建任务；冷重启不把旧进程描述成存活，不因重试重跑任务；不确定创建返回明确状态供查询。重复结束安全，过期请求不执行。幂等日志与操作副作用间的不确定窗口有恢复规则和测试。持久操作缺少 `createdAtUnixMs` 时拒绝；重试保留原时间，未来时间和超过 24 小时的请求不执行；覆盖记录被淘汰后再次提交旧请求。

### A07：背压和配额（P1；R06/R07）

1. 终端一持续高输出，客户端暂停读取；终端二执行交互输入。
2. 超过客户端发送队列、单终端历史和会话总配额；恢复读取。
3. 注入无写权限、磁盘满和半写状态文件。

通过：PTY 持续排空，终端二可交互；内存受配额约束；慢客户端重同步，无静默控制事件缺失；服务不崩溃，错误可恢复。

### A08：App 退出与关闭语义（P2；R01/R12）

1. 在独立 App 配置创建受管任务，关闭窗口、退出 App，再启动并附加。
2. 使用“分离”，再次附加；分别关闭受管 Pane、标签及显式结束终端。
3. 检查事件记录、Agent 状态和实际进程。

通过：关闭窗口/退出/分离均保活；关闭 Pane/标签和显式结束只结束对应资源，UI 确认准确列出运行任务影响；分离不写成 `session ended`。

### A09：旧数据兼容与迁移（P2；R01/R07）

1. 导入缺少远端字段的旧工作区，保留其中正在运行的非受管终端。
2. 执行布局托管迁移，注入服务不可达和持久化失败，再执行成功路径。
3. 重开 App，查看旧终端及新受管布局。

通过：旧数据可读、旧 PTY 未被结束；失败回滚；成功创建新实例并明确标识。文件/Web Pane、普通手动 SSH 及本地路径功能不回归。

### A10：SSH target 与认证（P3；R09）

1. 连接 alias、URI、自定义端口、IPv6、ProxyJump，以及实际 `root@ubuntu@orb`。
2. 使用配置解析到同 hostname 的不同 target，检查保留的原始配置。
3. 模拟未知主机密钥、私钥口令未加载、认证拒绝、目标以选项开头和包含 Shell 元字符。
4. 分别开启/关闭 SSH 配置管理，检查用户保活选项优先、私有 control socket 清理和已有用户复用连接不受影响。

通过：OpenSSH 语义保持正确；非法输入在连接前拒绝；后台不弹无限等待提示、不自动接受密钥、不记录凭据；attention 给出精确目标和修复入口。

### A11：安装与兼容（P3；R10）

1. 在测试目录无二进制时执行设置，分别取消与完成安装。
2. 注入错误平台、摘要不匹配、签名失败、空间不足、上传中断。
3. 运行不同发行版本但协议兼容服务，然后再次连接；测试不兼容服务。
4. 指定自定义开发二进制，测试错误平台、显式接受及未提供交互授权的后台连接；停止目标服务，验证后台进入 attention 而不重启。

通过：取消/失败不保存机器、不替换可用二进制；兼容服务 PID 和任务 PID 不变；不兼容服务需要显式处理，不被后台停止。

### A12：远端目录与本地边界（P3；R02）

1. 在本地/远端建立同名但内容不同的测试目录。
2. 远端创建终端，执行 `pwd` 和标记文件读取；测试不存在目录。
3. 点击远端路径、打开 File Pane、触发本机目录补全及 help 探测。

通过：终端只使用远端目录；失败明确定位远端；本机文件访问不因同名路径被触发，不存在目录不自动回落。

### A13：多机器与命名会话（P4；R04/R05）

1. 建立 Local、两个保存配置及两个命名会话，包含同 hostname 场景。
2. 分别修改各会话布局，重命名配置，再禁用/移除其中之一。
3. 停止一个命名会话、尝试删除活动会话、停止后删除。

通过：配置/会话身份正确隔离；重命名不重连；禁用/移除仅分离；停止限定本会话；活动删除被拒绝；删除不影响其他会话。

### A14：连接状态和配置恢复（P4；R06）

1. 一配置连接黑洞地址，另一配置正常连接；启动 App 并在 Local 输入。
2. 用虚拟时钟验证退避与心跳，再中断真实测试连接至少 60 秒后恢复。
3. 连接中切换配置，注入旧代回调；破坏机器配置文件后修复。

通过：Local 不等待远端，其他连接持续可用；按规定进入重连/attention；缓存明确 stale，断线输入不投递；重连不抢焦点；坏配置不清空有效连接。

### A15：共享结构、焦点与画面兴趣（P4；R07）

1. 两客户端连接同一命名会话并查看不同标签；在一端创建、拆分、关闭和调整布局。
2. 同时更新同一布局，检查 revision 冲突；该条继承原 A06 的要求，必须用真实布局事务并发提交同 revision 修改验证冲突识别，不得以协议字段或通用 revision 单测代替。切换活动机器并观察画面通道计数。
3. 在隐藏终端持续输出，再切回并取得写权。
4. 在来源客户端保留终端/本地文件混合布局，确认第二客户端只取得终端共享结构，本地资源关联仍在来源客户端正确恢复。

通过：结构一致、客户端焦点独立；隐藏画面订阅取消确认后不再发送该画面帧，元数据继续；重新可见先快照后输入。只允许合法租约来源调整尺寸。

### A16：Agent 状态与通知（P5；R08）

1. 对当前 provider 注册表逐一运行 fixtures；记录每项状态权威和恢复能力。
2. 真实运行至少一个完整 hook 类型和一个屏幕检测类型，触发运行、等待批准、取消、完成和退出；滚动画面并隐藏机器。
3. 两配置连接同一服务，模拟事件重发、乱序、实例替换和断线。

通过：权威不竞争，后台仍更新；等待状态由有效证据产生；完成未读正确清除，重复事件只通知一次；断线不伪造完成。真实工具条件不足必须记录未完成，不把 fixtures 当作真实验证。

### A17：冷恢复与历史（P6；R11）

1. 保存多工作区布局，关闭历史记录，停止并重启服务。
2. 开启历史后重复，检查历史标记、权限、配额、清除及隐身排除。
3. 注入损坏快照、截断历史和不兼容 schema。

通过：paneID 稳定、新 terminalID/PID 明确变化；关闭历史时不写屏幕文件；回放不表示任务存活；损坏状态有恢复入口，不任意执行旧命令。

### A18：Agent 原生恢复（P6；R11）

1. 保存已验证 provider 原生会话引用，冷重启后连接一次并提供尺寸/主题。
2. 在未聚焦标签放置可恢复实例；两客户端同时连接。
3. 测试恢复关闭、重复/过期/非法引用、CLI 不存在和恢复失败。

通过：每个有效引用只恢复一次且覆盖后台标签；在正确远端执行；失败创建明确的新 Shell 状态；分离重连不运行恢复命令。记录对话恢复与原进程存活的区别。

### A19：完整 TUI 与手机（P7；R03/R12）

1. 在 SSH shell 运行 `aster-session ui`，连接与 Mac 相同的会话，完成工作区/标签/分屏导航和输入。
2. 在实际手机/平板 SSH 客户端重做导航、文本粘贴、窄屏交互和分离；记录客户端和屏幕尺寸。
3. 测试 `Ctrl+B q`、字面前缀、异常退出、直接 attach、observer 和 controller。

通过：完整工作区可操作且状态与桌面一致；分离后进程存活，宿主终端恢复正常；观察者不能写入。单 Pane attach 或仅桌面缩窄均不能替代本用例。

### A20：配置与图片桥接（P7；R13/R14）

1. 设置不同本地/服务端主题与键绑定，切换模式并重载；执行远端自定义命令。
2. 从 Mac 剪贴板粘贴图片，比较远端文件摘要，核对输入只有路径且没有回车。
3. 测试超限、取消、上传失败、断线、粘贴期间切换终端/机器或丢失租约，以及临时文件清理。

通过：配置在规定位置生效，不重启服务；路径仅投递到原目标；失败不粘贴、无半文件；配额/TTL 生效，图片内容不进诊断。

### A21：GUI/CLI 对等与目标限定（P7；R17）

1. 为机器管理、会话、工作区/标签/窗格、attach/observe/control、Agent、恢复设置、图片上传和更新入口逐项填写 GUI/CLI 操作矩阵。
2. 执行结构化列表及写入，测试关闭 IPC 写权限、敏感会话权限和目标缺失。
3. 切换 GUI 活动机器后重发既有 CLI 命令，检查实际目的地。

通过：所有操作有可调用接口；GUI 选择不改变显式 CLI 目标；缺失或歧义目标被拒绝；权限关闭时远端写入同样被拒绝，不能通过 bridge 绕过。

### A22：更新与实时交接（P8；R15）

1. 使用受管测试版本升级客户端，证明兼容旧服务继续运行。
2. 普通服务替换分别取消和执行，记录进程影响及冷恢复。
3. 执行 handoff，连续输入/输出下检查身份、PID、画面和 Agent 元数据；在准备、FD 转移、接管确认前后分别注入失败。
4. 交接后让原子进程自然退出，再测试显式结束，检查进程回收和资源释放。

通过：成功 handoff 保留 terminalID/PID，epoch 更新、旧租约失效；接管前失败恢复旧服务，不丢失任务；接管后故障明确归属新服务；无双读、双写、僵尸积累和隐式破坏性降级。包管理安装未开放的 handoff 明确显示不可用。

### A23：平台、稳定性与性能（P8；R06/R16）

1. 在 Linux/macOS × x86_64/arm64 实机或虚拟机运行 A01、A03–A07、A19、A22；至少一组普通用户权限测试。
2. 24 小时运行 20 个终端，含静默、高输出、TUI、Agent、后台及慢观察者；执行 100 次网络断连和 100 次 attach/release。
3. 在同机同负载比较本地非受管基线与受管路径，测输入到画面延迟、启动时间、CPU、RSS 和 FD 数。

通过：无崩溃、死锁、丢失受管任务或持续 FD/内存泄漏；预热后 FD 回到初始值 ±5；相同静态状态下 RSS 回收后不持续单调增长，历史增长满足配额。OrbStack 低延迟环境输入到画面 p95 ≤100ms，黑洞远端不令 Local 启动相对基线增加超过 200ms。超标必须修复或修订规格并说明证据，不能静默略过。

### A24：安全、回归与完整性（P8；R01–R17）

1. 测试跨用户 socket、伪造引用/租约、路径穿越/符号链接、协议炸弹、非法上传路径、远端 OSC 剪贴板和本机文件/命令副作用。
2. 回归旧会话迁移、非受管终端、文件/Web Pane、录制隐身、IPC、通知及 App 退出。
3. 执行全量运行时测试、Swift 非并行测试和 App 打包/启动；核销全部需求与阶段任务，检查用户文档只描述已实现行为。

通过：安全边界未绕过，所有强制测试通过；R01–R17、P0–P8 和 A01–A24 证据齐全。构建可用不等于已签名公证或发布，分别记录。

## 4. 交付记录格式

每阶段记录任务已实现/未实现、用例已通过/失败/未执行、平台限制、测试 commit 和证据位置；附上未完成原因及解除条件。最终记录分别列出实现、验证、提交、合并、构建、签名公证、发布状态，不把后续动作混入“完成”。
