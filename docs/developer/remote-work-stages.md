# 远程工作模式分阶段实施

状态：P0、P1、P2 已通过，P3–P8 未开始。目标和固定规则见 [设计草案](remote-work.md)，验收编号见 [验收规格](remote-work-acceptance.md)。严格按阶段推进；前置验收失败时修复该阶段，不以降级实现跳过门槛。

本任务执行边界：P2 已按 A08、A09 完成并交接；P3–P8 保留为整体规格，由其他 agent 接续，不在本任务自动启动。

## 执行合同

- 每阶段开始先读取当前代码、任务 worktree、阶段记录与上阶段证据。实施时创建或复用本任务 feature worktree，保留已有改动。
- 任务列表是必须完成的集合。每个任务以代码/协议/文档工件和验收记录交付，不能用待办、假数据或仅设计说明替代。
- 为每阶段建立 `docs/developer/remote-work-evidence/pN.md`，记录实际命令、环境、commit、测试结果、截图/日志位置、失败与修复；尚未执行时标记“未验证”。证据正文脱敏，原始大文件放忽略的构建输出目录。
- 按需求和改动影响面选择定向测试。Swift/AppKit 改动只运行相关用例；Zig 改动只运行相关模块、实际链路与该阶段平台构建；协议改动执行受影响的 Swift/Zig 同样例互操作测试。不得默认运行全量测试。纯文档变更验证链接、需求覆盖和格式。跨模块变更先列明影响链路，再确定测试集合。
- UI 阶段使用独立配置和专用测试窗口实际操作；不能以调用控制器方法代替键盘、关闭窗口、切换机器和重连的真实验收。
- 阶段失败要写明阻塞能力及影响的 R/A 编号。修订架构必须同步三份规格及阶段记录；不能静默换成 tmux/Herdr 或重跑命令来通过保活测试。
- 阶段完成后更新状态，不自动提交、合并或发布。

- [x] P0.2 建立 Ghostty VT 适配层，实现输入解析、主/备用屏幕读取、模式提取、尺寸变更和规范化画面编码；所有内部 API 调用限制在此层。
- [x] P0.3 建立一次性 PTY 与服务、bridge 的真实链路；本地 Ghostty 启动 bridge，从独立服务接收画面，发送输入和尺寸。
- [x] P0.4 编写协议 v1 schema 与跨语言样例，定义 framing、握手、身份、请求/事件序号、租约、幂等键、错误、能力和资源上限。明确二进制块与控制帧的边界。
- [x] P0.5 用跨读块 UTF-8、宽字符、组合字符、备用屏幕、光标定位、鼠标模式、bracketed paste、查询响应及图形状态验证完整快照→增量切换；验证输入不会被桥重复编码。
- [x] P0.6 增加运行时 build/test 脚本，与 macOS App 构建分离；构建产物保持忽略。将 Linux 产物只放入 OrbStack 本次测试目录，不修改系统默认安装。

**交付物：** 运行时构建、VT 适配、最小服务/bridge、协议 schema/fixtures、构建测试脚本、P0 证据。

**验收：** A01、A02、A03 通过；macOS Ghostty 和 OrbStack 后端跑通同一链路，终端查询每次只收到一个正确响应，快照后画面和输入模式一致。

**退出门槛：** P0 任一终端语义不成立即停止后续 UI 接入，修复 VT/bridge 协议。此阶段不开放用户级后台终端功能。
