# Aster 用户帮助

## Aster 能做什么

Aster 是完全使用 AppKit 构建的原生 macOS 终端工作区。它支持完整彩色终端、`vim`/`top`/`fzf` 等全屏程序、多标签和任意方向分屏，还能把文件浏览器、编辑器与预览放进同一个工作区。

当前产品终端由 Ghostty 内核提供。普通 Shell、全屏 TUI、选择、复制粘贴、滚动、完整
查找、标题、目录、通知、只读、Vi / Mark / Hint Mode、inline Autocomplete、Agent 状态
和命令 Outline 均可用。Ghostty 自身处理 OSC 8 显式链接；Hint Mode 当前枚举可见 URL
与路径，不枚举显示文字背后的隐藏 OSC 8 URI。

## 诊断日志与反馈

从“帮助 → 反馈问题…”可以填写可选的问题描述，再选择“保存诊断包…”或“分享…”。Aster 会在你点击操作后生成 ZIP，并交给 macOS 的系统分享面板；不会自动上传任何信息。诊断包只包含最近 7 天、最多 20 MB 的 Aster 应用日志、版本和系统摘要；Shell 异常只记录退出类型、状态码和会话标识，不包含终端输入输出、命令、路径、环境变量、配置、剪贴板或系统崩溃报告。你也可以在该页点“打开日志文件夹”先自行查看 `~/Library/Logs/Aster`。

## 开始使用

1. 双击 `Aster.app`，应用会恢复上次工作区；首次启动则在主目录创建登录 Shell。
2. 直接点击终端并输入命令，无需额外输入框。
3. 按 `⌘T` 新建标签，按 `⌘D` 向右拆分，按 `⇧⌘D` 向下拆分；完整分屏命令见“显示”菜单。
4. 按 `⌘K` 打开命令面板，可搜索所有主要动作。

### 多窗口、置顶与画中画

- 按 `⌘N` 新建独立工作区窗口；每个窗口拥有自己的标签、分屏和恢复快照。正常退出后会恢复仍打开的附加窗口，主动关闭的窗口不会在下次启动重新出现。
- 拖动垂直或水平标签到另一个 Aster 窗口可移动标签；拖到所有窗口之外会创建新窗口。该操作保留正在运行的 PTY、滚动历史、编辑草稿和 Agent 状态。
- “显示 → Pin Window”切换当前工作区置顶；独立设置窗口不会改变置顶状态。“Picture in Picture”可固定当前 Pane，或让浮动面板跟随活动 Pane。

## 标签与三种布局

在“设置 → 外观 → 布局”中选择垂直、顶部或底部，主界面会立即切换到所选布局，无需关闭设置窗口。垂直布局默认使用 220pt 窄侧栏。拖动左栏与中央内容之间的分隔线可在 180...360pt 内调宽；分隔线悬停时灰色加深，双击恢复 220pt。拖动只调整宽度，不会折叠侧栏。整行标签显示目录名（主目录显示 `~`），切换标签时名字保持不变；有命令正在运行的标签会在行右侧显示旋转指示器，鼠标移到标签行时该位置换成 `×`，点击可直接关闭该标签，关闭后台标签不会先切换过去。旧版侧栏宽度会在该工作区窗口首次建立 Panel 布局时迁移；之后每个工作区窗口独立保存自己的左右宽度。标签行显示为左右留边的圆角卡片，选中和鼠标悬停都会给卡片加底色。鼠标移到侧栏任意位置时，顶部右侧会浮现「+」（新建标签页）；把鼠标再往上移到红绿灯那一行，旁边会额外浮现折叠图标（隐藏标签栏）。点击标签切换时「+」保持显示，不会闪一下消失；折叠后把鼠标移到窗口顶部（红绿灯右侧）会再次浮现「+」和展开图标，也可通过“显示”菜单的“显示/隐藏标签栏”恢复。新标签默认自动追加，标签面板可保持默认显示或在只有一个标签时隐藏；右键标签可快速分屏、打开文件浏览器或关闭标签。终端内容直接延伸到窗口底部，不再显示 `workspace · 路径 / PANE / UTF-8` 状态栏。窗口尺寸会在拖动结束后保存，“窗口大小”可恢复默认尺寸。

选择“顶部”时，窗口最顶一行是红绿灯与中央目录胶囊（项目名称）共处的标题带，标签条横贯其下一行，标签不会顶进红绿灯区域；选择“底部”时标签条贴住窗口底边，标题带保持在窗口顶部。两种横向布局的标签宽度随标题自适应：当前标签显示为主题色圆角胶囊，右端带 `×` 可直接关闭；其他标签是纯文字，鼠标悬停出现底色反馈，点击切换，右键菜单仍提供重命名、分屏、文件浏览器和关闭。正在运行、等待输入等状态徽章显示在对应标签右端，标签过长时按尾部截断。标签后面的「+」新建标签页；命令面板改用 `⌘⇧P` 或“显示”菜单打开，不再占用标签条图标位。拖动标签仍可移动到其他窗口。

点击 `TABS` 右侧的整理图标可打开标签菜单：`No Grouping / By Project / By Date` 控制分组，`Created Time / Updated Time` 控制最新标签的排序依据，`Insert Divider` 在当前标签后加入分隔线，`Remove All Dividers` 清除全部手动分隔线。分组和排序选择会自动保存；只有主动选择分组时才显示分组标题。按项目分组时存在两种明确类型：本地 project 使用文件夹图标，组头和标签都只显示末级项目目录名（如 `aster`）；SSH project 使用电脑图标，并按最终服务器 `hostname` 单独分组。两种类型拥有不同 identity，SSH tab 不会混入发起连接的本地 project。完整本地路径仍作为内部身份和 tooltip，因此不同父目录下的同名项目不会被并进一组。`⌘T` 或侧栏「+」新建的本地标签会从当前标签的目录启动，因此直接出现在当前本地 project 分组里。在 Pane 中提交 `ssh` 命令后，Aster 会异步用 OpenSSH 配置解析最终 `hostname`：例如 `ssh root@ubuntu@orb` 可按 `~/.ssh/config` 解析到 `127.0.0.1`，随后建立独立 SSH project；SSH 失败、退出或回到本地 Shell 后自动恢复本地目录归属。

右键标签并选择“重命名标签页…”可以固定名称，或添加会随运行程序继续更新的动态前缀；“恢复自动标题”重新使用程序发出的 OSC 标题。名称、前缀和最后标题会随工作区恢复。当前 Pane 里运行着已集成的 Agent CLI（Claude Code、Codex 等）时，标签会改为显示该会话的标题（由会话里的第一条有效提问推导，发出首条 prompt 后稍等片刻出现）；你手动固定的名称仍然优先，Agent 退出后恢复原标题。

在“设置 → 外观 → 标签栏”可选择新标签位置：“自动”会把空标签放到当前分组末尾、把带目录或文件的标签放到当前标签后；也可固定为列表末尾或当前标签之后。无论位置如何，`⌘T` 新建的标签都继承当前标签的实时工作目录；没有可继承的标签时从主目录启动。

窗口失去键盘焦点时，整个工作区会朝主题底色轻微褪色，终端光标同时停止闪烁（形状不变），便于在多窗口之间辨认哪个正在接收输入；重新聚焦即恢复，期间的第一次点击仍会正常落到终端上。终端右侧不再显示会闪现的系统滚动条，滚动历史通过滚轮、键盘和 `⌘F` 查找访问。

主窗口右侧顶部与终端画布使用完全相同的背景色，普通状态显示活动 Pane 的程序标题。把鼠标移到标题上会显示当前工作目录的灰色路径胶囊；活动 Pane 运行 Agent 会话且已有标题时，胶囊改为显示会话标题，完整工作目录退到悬停 toolTip。点击后可直接设置标签名称/前缀、复制路径、在 Finder 或已安装编辑器中打开、预填 Git 命令、分屏，以及打开当前查找、全局查找、Jump to 和命令面板。“Notifications & Privileges”会跳到 Shell 通知设置。Git 写操作只预填到终端，仍由你回车确认。
Aster 会为 zsh、Bash 和 fish 加载签名的 Shell Integration；支持时，OSC 7 目录会实时同步到侧栏和会话快照，`file://localhost/...` 形式会自动转换为 `~/...` 可读路径，并以本地目录形式安全恢复。

### Shell Integration 与命令导航

- zsh 与 fish 只对 Aster 启动的当前会话注入资源；Bash 和 tmux 子 Shell 使用 `.bashrc`、`.bash_profile`、`.zshrc` 或 fish `conf.d` 中带清晰起止标记的受管区块。Aster 只改动区块本身，保留用户内容、权限和符号链接。
- “设置 → Shell → Shell 集成”默认开启。关闭前会确认并移除受管区块；命令通知、徽标等依赖设置值不会丢失。单个 Shell 可在启动前设置 `ASTER_DISABLE_INTEGRATION=1`。
- `Command+Page Up / Page Down` 跳到上一条或下一条命令；已经被滚动历史裁剪的命令不会跳到错误文本。命令开始时标签显示运行指示器，结束后按设置显示 `✓` 或非零退出码。
- Ghostty Shell Integration 负责提示符标记和命令跳转；旧引擎专属的“选区 Backspace 安全删除”在当前版本不启用。

## 常用目录

Aster 会在本机记录你通过终端访问的目录，并按“使用频率 + 最近时间”维护最多 100 项排名，为后续快速打开和 `jump` 使用。最近一小时访问过的目录权重最高；同一查询会优先匹配完整目录名，再匹配名称前缀、名称包含和完整路径。

“设置 → Shell → 常用目录 → 自动记录访问目录”默认开启；关闭后，新的 OSC 7 目录变化不再写入排名。被加入忽略列表的目录不会因再次 `cd` 自动出现，必须先取消忽略。全部数据只保存在本机，不会上传或自动同步。

## 分屏与 Pane

“显示”菜单集中了全部分屏命令。

**拆分**

- `⌘D` 向右拆分、`⌥⌘D` 向左拆分、`⇧⌘D` 向下拆分、`⌥⇧⌘D` 向上拆分。

**缩放与大小**

- `⇧⌘↩` 缩放拆分：把当前 Pane 临时放大到整个工作区，再按一次还原。放大期间其它 Pane 继续运行；继续拆分或切换聚焦会自动还原。
- **双击窗口顶部标题条**（路径胶囊所在的空白处）放大/还原整个窗口，与「显示」菜单的「缩放」项等效——原生标题栏被隐藏后手动补回的双击手势。
- “调整拆分大小”子菜单：`⌃⌘=` 等分拆分，`⌃⌘↑ / ↓ / ← / →` 按 5% 移动当前 Pane 所在的分隔条（方向就是分隔条移动的方向）。
- 分隔条平时是一条灰线，鼠标靠近时会加粗并加深灰度（保持灰色，不跟随主题变色）；直接拖动即可调整大小，**双击分隔条**恢复等分。比例随会话保存，终端自动收到新的行列尺寸。

**拖动 Pane 重排**

- 把鼠标移到任意 Pane 的顶边中央，会浮现一个灰色小胶囊；指针压上去后胶囊变长、灰色加深，光标切换为抓手。胶囊固定用系统灰，不跟随终端主题变色。分屏时 Pane 内容会让出顶条高度，胶囊不会压在第一行文字上。
- 按住胶囊拖动即可搬动整个 Pane，终端进程和滚动历史都不会重启。拖动时落点会高亮：
  - 落在另一个 Pane 的**边缘**（四边各 25%）：用主题色高亮该侧一半区域，松手后 Pane 插到这一侧。
  - 落在另一个 Pane 的**中心**：用绿色高亮整块，松手后两个 Pane 互换位置，分屏结构和比例都不变。
- 拖回自己身上不会有高亮，松手即取消。

**聚焦与关闭**

- “聚焦面板”子菜单：`⌥⌘↑ / ↓ / ← / →` 聚焦相邻 Pane，`⌘]` / `⌘[` 在所有 Pane 之间循环。
- 点击任意 Pane（包括终端内容区）都会把它设为当前 Pane，查找、中断、拆分和关闭都作用于它。分屏时非当前 Pane 的内容整体朝主题底色轻微褪色（变灰），当前 Pane 保持原色，不画高亮边线；褪色不影响点击，点非当前 Pane 的第一下照样落到终端上并立即恢复原色。
- `⌘W` 关闭当前 Pane；只剩最后一个 Pane 时才关闭整个标签页。`⇧⌘W` 始终关闭整个标签页，`⌥⌘W` 只关闭 Pane。
- 分屏时把鼠标移到 Pane 顶边，右上角会浮现灰色 `×`；悬停时颜色加深、光标变为手型，点击即关闭该 Pane（与 `⌘W` 同一语义，会记入「最近关闭」）。
- 关闭后焦点会落到相邻的 Pane，而不是跳回第一个。

## 文件浏览器、编辑与预览

详情面板的 Files 页以当前工作目录为根。双击 Markdown、reStructuredText、HTML、SVG 或普通源码会在右侧以可编辑 Source 打开；图片、PDF、富文档、diff、Agent transcript 和二进制保持只读预览。目录用箭头或双击在树内展开。右键菜单包含：

- `Open`：使用 macOS 默认应用；可执行文件或 `.app` 会再次确认。
- `Open in Aster`：可选 Current Pane、New Tab、New Window、Split Right/Left/Top/Bottom。
- `New File…` / `New Folder…`：文件选中时创建在其父目录，目录选中时创建在目录内部；不会覆盖同名项。新文件会在右侧以可编辑 Source 打开。
- `Rename…` / `Move to Trash`：重命名后已打开 Pane 会继续跟踪新路径；删除进入系统废纸篓，可以恢复。
- `Copy Path` / `Copy Relative Path` / `Reveal in Finder`：相对路径以当前 Files 根目录为准且不带 `./`。

File Pane 顶部左侧提供模式胶囊、发送到 Chat 和共享；中间显示文件名与更多菜单；右侧显示 `✓ Saved`、`Edited`、磁盘冲突或错误，并提供保存和关闭。Markdown、reStructuredText、HTML 与 SVG 使用 code/eye 在可编辑 Source 和 Preview 间切换；普通源码使用 code/lock 就地锁定或解锁。切换会保留源码选区、滚动位置和撤销记录；`⌘S` 原子保存，不会自动保存。存在未保存内容时关闭仍会询问保存、放弃或取消。外部程序修改文件时，未编辑的 Pane 自动重载；本地已有修改时显示 `Modified on Disk`，可从 `… → Reload from Disk` 明确放弃本地内容。

Preview 支持 Markdown（含 GFM 表格、任务列表等）、reStructuredText、HTML、SVG、常见图片/GIF、PDF、diff、Office/媒体/字体 Quick Look、二进制 hex 和 Aster 已识别的 Agent transcript。HTML/SVG/Markdown 预览禁用 JavaScript 与网络请求；Agent transcript 以会话视图渲染（角色区分、Markdown、工具折叠），可 Resume 或 Fork。二进制 hex 只按可见行绘制，超大文本和二进制只读取有界内容，避免单个 Pane 占满内存。远程 SSH 路径暂不支持 File Pane。

普通 UTF-8 文件可从 File Pane 点气泡图标“发送到 Chat”；文件必须是非符号链接且不超过 64 KiB，内容会先移除控制字符并遮盖常见 secret。无法读取或保存时，Pane 会显示明确错误，未保存内容不会被清除。

把 Finder 文件或目录拖到 Pane 边缘，可按高亮方向创建预览、文件浏览器或继承目录的新终端；把纯文本拖到终端会经过与粘贴相同的危险内容确认。HTTP/HTTPS URL 会在对应方向创建 Web Pane。一次最多处理 32 个 URL，符号链接和特殊文件不会被读取。

### 打开终端中的文件与链接

按住 `⌘` 时，终端视口里所有可点击的目标都会显示实线下划线；松开即消失。按住 `⌘` 悬停在目标上鼠标变成手形，点击即用系统默认应用（或“打开方式”里选的目的地）打开。Aster 能解析绝对路径、`~/`、`./`、基于当前 OSC 7 目录的相对路径与裸文件名（如 `Makefile`、`site/README.md`，只有在当前目录下真实存在时才会标记）、`path:line:column`、普通 URL、`mailto:`，以及程序发出的 OSC 8 显式链接。远端 Shell 里的相对路径不会被当成本机文件。

“设置 → 控制 → 链接协议”里“自动识别链接协议”选“全部”可识别所有合法协议，选“自定义”则把普通文字 URL 限制为 `http`、`https`、`file`、`mailto` 加下方列出的自定义 scheme。OSC 8 显式链接不受列表限制，但不会绕过安全检查。“显示链接预览”控制按住 Command 悬停时左下角的完整目标提示，关闭后链接仍可点击；本地相对路径会按当前可信目录展开为绝对路径。提示使用固定半透明圆角底：浅色外观为黑底白字，深色外观反转为白底黑字，不会被当前终端主题染色。“重置安全提示”清除所有“始终允许”记忆。

“设置 → 控制 → 打开方式”分别选择链接、文件和文件夹的目的地。本地普通文件与文件夹可直接在 Aster 的 Editor / File Browser Pane 中打开，也可交给系统默认应用或 Finder；HTTP/HTTPS 网页可在只允许网页导航、不开放本地文件和自定义协议的 Web Pane 中打开。默认 Git 客户端和“自定义打开方式”都按 bundle ID 保存，应用移动或升级后仍由 macOS 重新查找。

首次打开外部网站、非标准 scheme（如 `codex://`）、可执行文件或 `.app` 时，Aster 会询问打开一次、始终允许或取消；可在同一设置区域点击“重置安全提示”清除全部例外，按钮会短暂显示“已重置”。可执行授权绑定当前文件身份，文件被替换或修改后会重新确认。导入设置不会导入另一台机器的安全授权。为避免阻塞或访问系统设备，FIFO、socket 和设备文件始终拒绝打开。

### 复制与粘贴

- 按 `⌘C`、使用“编辑 → 复制”或终端右键菜单复制选区；按 `⌘V` 粘贴。设置中可开启“选中即复制”“复制时去除行尾空格”和“复制后清除选区”，三项默认均关闭。启用“选中即复制”时会保留高亮以便继续扩展选区，不执行复制后的清除设置。
- 粘贴保护默认开启。内容包含多行、末尾换行、`sudo`/`su` 或不可见控制字符时，Aster 会显示有界预览并要求选择“仍然粘贴”或“取消”。全屏 TUI 或可信 bracketed paste 可跳过普通多行告警，但不可见控制字符始终要求确认；内嵌的 bracketed 结束标记会被转换成可见文本，不能提前执行后续命令。
- “编辑 → 粘贴为”当前保留括号粘贴和“粘贴并在 Composer 中继续”。依赖旧引擎私有输入状态的粘贴选区、Base64 文件和 Shell 参数转义入口暂时置灰。
- “粘贴并在 Composer 中继续”会在 Agent Composer 可用时交接剪贴板文本；未打开 Composer 能力时该右键项置灰。
- “编辑 → Prompt 队列…”在当前终端 Pane 中可用，不会因 Claude Code 或 Codex 的识别状态变化而置灰。它在 Pane 底部打开输入条；按 Return 或右下角上箭头把内容加入上方列表。已在设置里安装 lifecycle hook 的 Claude Code / Codex，队列会自动发送：Agent 空闲（等你输入下一条）时立刻发出队首，正在执行时先排队、等这一轮结束再发，并且一次只发一条。等待权限确认（awaiting-input）时不会自动发送 —— 那时屏幕上是确认选择器，替你回车等于批准了一次工具调用。没有安装 hook 的普通 CLI 保持全手动。
- 任何时候都可以点击某项左侧的 ↳ 图标立即插队提交，右侧垃圾桶可移除尚未发送的项。关闭输入条不会取消队列，展开按钮可输入多行，队列仍受只读和终端输入模式限制。
- “编辑 → 发送到聊天…”以及终端右键“发送选区到 Chat”会打开确认面板。可同时选择当前选区与当前终端 transcript，并从当前工作区所有运行中的 Claude Code/Codex Pane 选择接收端；点击 Send 会以普通键入预填 Comment 和清理、脱敏后的上下文，不会自动回车。

终端程序可用 OSC 52 请求访问系统剪贴板。“设置 → 控制 → 复制与粘贴”分别提供“允许 / 每次询问 / 拒绝”：写入默认允许，读取默认每次询问。每次询问只授权当前请求，不会记住；连续请求在提示后有 5 秒安全冷却。导入配置不能把读取权限静默改成“允许”；拒绝或超限请求不会读取剪贴板。

### 选择终端文本

- 拖动选择字符，双击选择单词，三击选择整行；按住 `Shift` 点击可从现有锚点扩展。按住 `Option` 拖动会选择矩形列。
- Vi / Mark Mode 可用键盘移动和扩展选区；鼠标选择与 `Option` 矩形选择由 Ghostty 处理。
- vim、tmux 等程序开启鼠标报告时，`Shift` 是否保留为本地选择由 Ghostty 与前台程序协商。
- “设置 → 控制 → 选择”的选中即复制、输入时清除、复制后清除和行尾空格处理会实时应用；旧引擎专属的 Shift 方向键与退格删除开关暂不生效。

### 滚动终端历史

- 滚轮或触控板浏览 normal buffer；平滑滚动开启时按像素移动，并在手势结束时对齐字符行。向终端输入会回到最新内容；新输出只在视口已位于底部时跟随——上滚查看历史时，正在运行的命令或 TUI 的持续输出不会把画面拉回底部。
- `Shift+Page Up / Page Down` 向上或向下翻页，`Shift+Home / End` 跳到最早或最新内容；`Command+Page Up / Page Down` 按 Shell 命令跳转。相同命令也位于“显示 → 终端滚动”。
- “设置 → 控制 → 滚动”可关闭平滑滚动，并选择滚过末尾或开头时，把最后内容行、光标行或第一内容行停在视口顶部、中部或底部。全屏 TUI 的 alternate screen 始终禁用越界空白。

### 渲染与持续输出

Aster 使用 Ghostty 的 Metal renderer。PTY 读取、VT 状态、scrollback 和绘制由同一终端
内核管理，Aster 只响应最终渲染请求；持续大量输出不再经过旧的 AppKit 字节批次与
Core Graphics 网格路径。

### 输入与安全键盘

- 键盘、IME、修饰键和 Kitty 键盘协议由 Ghostty 编码；Aster 不再额外猜测普通 Shell 的行编辑序列。
- “编辑 → 插入”可选择一个或多个文件/文件夹路径，或调用系统交互式截屏；结果会以安全转义后的路径预填到当前前台程序的输入框（包括 Codex/Claude 等 TUI），但不会自动执行。“编辑 → Insert from iPhone”会显示附近可用的 iPhone/iPad 拍照或扫描入口，完成后通过同一入口把私有临时文件路径插入当前输入框。手机导入只接受常见图片或 PDF，单项最大 32 MiB。
- “编辑 → 编辑器”（`⇧⌘E`）会在当前 Pane 底部打开 Composer 输入区，可直接输入、发送或加入 Prompt 队列；不会弹出文件选择器。需要编辑本地文件时，请从“文件”、文件树或路径入口打开。“Prompt 队列…”（`⇧⌘M`）和“发送到聊天…”分别打开当前终端的队列输入条与发送确认面板。
- 新安装默认关闭“Option 作为 Meta”，因此 Option 可继续输入重音和特殊字符；需要 Emacs/Vim 风格 Esc 前缀时可在“设置 → 控制 → 键盘”选择左右两侧、仅左侧或仅右侧。VT100 数字键盘模式默认允许，关闭后即使前台程序请求 DECKPAM，小键盘也保持输入数字。
- “设置 → 控制 → 鼠标”可配置右键为菜单、复制、粘贴、按选区自动选择或忽略；无论怎样设置，`Control + 右键` 始终打开菜单。还可选择 TUI 鼠标上报的绕过修饰键、输入时隐藏指针、悬停聚焦 Pane，以及在可靠 Shell 提示符行单击移动光标。
- “自动安全输入”默认开启。当前聚焦终端进入 canonical 隐藏输入（例如密码提示）时，Aster 会在输出到达及首个按键发送前启用 macOS Secure Event Input；Vim、less 等 raw-mode TUI 不会误占用。恢复回显、失焦、进程结束或切到其它应用后自动释放。也可从“编辑 → 安全键盘输入”手动开启或关闭；系统保护真实生效后，主工作区标题栏右侧显示蓝色 `SECURE INPUT` 胶囊。手动状态在 Aster 失活时暂停，切回后恢复。
- Codex、Claude 和普通 Shell 输入框保留 `Ctrl+A`、`Ctrl+E`、`Ctrl+K`、`Ctrl+U`、`Ctrl+W` 等常用行编辑控制键；Aster 的 `⌘←`、`⌥←` 等原生菜单快捷键不会占用这些组合。

### 字号与全屏

- 在“显示”菜单选择“增大字号”“减小字号”或“重置字号”，也可使用 `⌘=`、`⌘-`、`⌘0`。字号范围为 9–32pt，重置值为 13pt，并会同步应用到所有已打开终端。
- 选择“显示 → 进入全屏幕”或按 `Fn+F` 切换当前工作区窗口；进入后同一菜单项会显示为“退出全屏幕”。

### 只读模式

- Aster Vi / Mark / Hint Mode 使用 Ghostty retained buffer 的稳定坐标；输出或窗口 reflow 使旧锚点失效时会安全退出当前模式。
- “Shell → 只读模式”或 `⌘K` 命令面板按 Pane 切换只读。锁定后键盘、IME、粘贴和 TUI 鼠标报告不会到达程序；输出、滚动、选择、复制和查找仍可用。编辑器 Pane 也会停止接受修改。关闭并恢复工作区后只读锁不会保留。

### Autocomplete 与 Inline Suggestion


候选面板可见时，Tab 可直接接受首项；Return 在明确选中候选后接受，未选中时仍交给 Shell。
工具明确给出的失败纠错属于确定建议，即使另有历史候选也可优先显示行内修正。


候选面板最多同时显示 8 行，超出部分可以用上下键滚动，右侧的侧栏给出当前选中项的完整说明。面板打开后继续输入会按新前缀收窄，而不是关闭。自动面板先列出候选，不把第一条当作你的选择；用上下键选择后，Return 或 Tab 接受当前项。按一次 Esc 可以在本轮提示符内关掉它，再按一次 Esc 又能叫回来。把“Inline suggestion”和“候选面板”同时关闭等于完全停用该功能，内置规格库根本不会被查询。

Autocomplete 使用 Ghostty 的原始 PTY observer，继续显示 inline suggestion 和候选面板；
只有一个候选或已明确选中某个候选时才显示 inline suggestion；切换选择时，预览和说明同步变化。
预览使用当前终端字体，与输入保持同一行和同一基线，不覆盖 prompt 或已经回显的命令。接受候选、隐私过滤、本机学习与目录上下文规则保持不变。

**空提示符会推荐当前目录的常用命令、固定命令和 README 命令**，不会列出整个规格库。
上一条命令失败且能识别修正方式时，下一条提示符会优先显示纠错建议；继续输入可以忽略它。
Shell 自己的灰色建议占据行尾时，Aster 隐藏行内建议，仍可用候选面板选择。
狭小 Pane 会减少面板可见行数，避免覆盖输入行。

命令名打完、还没敲空格时（例如 `docker`），候选里除了同前缀的其它命令名，也会直接给出这个
命令的子命令和选项——按 Tab 想看的是「它能做什么」，而不是「还有哪些可执行文件叫 docker\*」。

Tab（或设置中的其他接受键）直接接受已经可见的建议，包括 zsh-autosuggestions 等 Shell 插件
画在光标后的建议；Aster 只发送建议后缀，不再触发 zsh 的「是否列出全部可能项」询问。
只有一个候选时只显示行内建议，不弹面板；已打开的面板收窄到一个候选也会自动收起。
有多个候选且没有可见建议时，接受键可打开候选面板。既无可见建议又无候选时，才交给 Shell 原生补全。

**按上下文补全**：`cd` 只列目录；命令子项位置不会混入无关项目文件。文件和目录名称包含空格、
单引号或双引号时，会沿用你已输入的引号与转义方式。选项支持 `--参数=值`，已经使用的非重复选项
不再推荐；`--` 后按位置参数处理。历史参数按当前目录和参数位置学习，例如常用分支在增加
`--force` 后仍可推荐；关闭本机学习会同时停用这类历史参数建议。

**动态候选**：当内置规格声明某个参数需要活数据时（`git checkout <分支>`、`brew install <formula>`、`npm run <script>`、`make <target>`），Aster 直接读取磁盘上已有的文件——`.git/refs`、`.git/packed-refs`、`.git/config`、`package.json`、Makefile、Homebrew 的 `Formula/` 与 `Cellar/` 目录。**Aster 绝不运行被补全的工具**：补全 `brew install` 不会触发 `brew update`，补全 `git checkout` 不会在你的仓库里执行 git。最近 check out 过的分支会排在更前面（读的是 `.git/logs/HEAD`）。需要真正运行工具才能取到的数据（例如 `git status --short` 的暂存清单）不做动态候选，退回普通文件补全。

Homebrew 4.x 默认走 JSON API：如果你的机器上没有 homebrew-core tap，也没有 API 名称缓存，`brew install` 只会补出已安装的包和第三方 tap 里的 formula。这是“绝不联网、绝不触发 `brew update`”的必然代价。

Aster 不会把 `package.json`、Makefile 或 justfile 里的脚本当成顶层命令主动推给你——上面那些只在规格明确要求该参数槽位时才读取。需要固定项目命令时，先在“设置 → Shell → Aster CLI”安装 CLI，然后在目标目录运行：

```bash
aster learn 'npm run deploy'
```

`aster learn` 的参数如果是 PATH 上的一个裸二进制名，它会改为在禁网、禁写文件的沙箱里运行该工具的 `--help`，解析出子命令与选项写进本机补全库：

```bash
aster learn ripgrep
```

这样生成的规格单独保存，点击“立即更新”刷新内置规格时不会被覆盖。重复对同一条命令运行 `aster learn` 会提升它的排序权重。

`aster ignore` 是 `aster learn` 的撤销，三种目标一一对应：

```bash
aster ignore ./old-project      # 不再把这个目录算进常用目录
aster ignore 'npm run deploy'   # 取消固定这条命令
aster ignore ripgrep            # 删掉这个工具的本机 help 规格
```

撤销固定命令时，如果你确实跑过它，普通使用历史会保留下来——只是不再被钉在最前面。内置 CLI 规格不是你学出来的，`aster ignore` 不会删它。

“本机学习”默认开启。学习库只保存脱敏后的命令、目录和计数，不保存输出；`--password`、`--token`、`--api-key` 等值会被移除，退出码 127、明显错误的长选项和“历史忽略模式”匹配项不会保留。内置结构不完整的命令会以 `--help`、`-h`、`help` 固定参数在禁网且禁止写入文件的沙箱中探测，并限制为 2.5 秒和 128 KiB。判定看的是「有没有选项和参数」而不只是「有没有子命令」——上游规格里 `docker` 就是 58 个子命令配 0 个选项，只看子命令会让它的顶层 flag 永远补不出来。探测会挑**最深的那个不完整层级**：`docker compose` 在上游规格里是个只有名字的空壳，Aster 会去探测 `docker compose --help` 而不是顶层。探测结果与内置规格按字段合并（子命令、选项取并集），不会把内置规格独有的嵌套结构冲掉；远程会话不会读取本机项目文件或运行本机 help 探测。关闭本机学习后，历史、固定命令、README、纠错与 help 探测全部停用，内置规格和文件补全仍可用。

Fig 命令清单不会后台更新。控制页会显示当前规格数量和版本；需要刷新时，在同一设置区域点击“立即更新”，本地 help 规格不会被覆盖。“清除…”可分别删除命令历史、固定命令和目录频率数据，不删除内置、手动更新或 help 规格。

### Unicode、双向文本与终端图片

- Aster 支持组合字符、CJK 双宽字符、emoji ZWJ/肤色/旗帜序列、text/emoji variation selector，以及 24-bit truecolor、256 色和完整 SGR 样式。圈字母数字默认按两列显示；可在“设置 → 高级 → 加宽 East-Asian-Ambiguous Block”选择其它 block。该宽度策略只影响新建标签和之后写入的字符。
- “设置 → 外观 → 文本”可选择关闭、标准或 discretionary 连字，并设置粗体、斜体与 blink 的渲染策略。blink 默认稳定显示；选择动画后才会闪烁。
- 双向文本默认开启。希伯来文、阿拉伯文和混合方向行按阅读顺序显示，但复制、查找和粘贴仍使用程序写入的逻辑顺序；左右键与鼠标命中跟随视觉位置。遇到自行排版 RTL 的全屏 TUI，可在设置中关闭。程序进入 ECMA-48 mode 8 时 Aster 会自动暂停隐式重排。
- 终端程序可以显示 iTerm2、Kitty 和 Sixel 图片。Aster 会限制输入、分片、解压、像素尺寸与缓存；损坏、取消或超限图片会被丢弃，不影响之后的正常终端输出。
- 应用包原样内置 Otty 1.3.1 使用的 JetBrains Mono、Office Code Pro 和 Symbols Nerd Font Mono，同时保留 Aster Nerd Symbols fallback；无需另行安装这些字体。即使选择的基础字体没有 Powerline 或 Nerd Font 图标，终端仍能解析 BMP 与补充平面符号。

### 任务进度、徽章与通知

终端程序可通过 `OSC 9;4` 报告百分比、不定进度、错误和完成状态；支持 Shell Integration 时，Aster 也会为“设置 → 高级 → 自动进度命令”列表中的常见慢命令自动显示运行状态。列表按空白分词前缀匹配，例如 `git push` 会匹配 `git push origin main`，但不会匹配 `git pushd`；清空列表即可关闭自动匹配。

标签会在名称右侧显示运行、刚完成、未读完成、错误和等待输入状态；Agent 在处理、请求确认、恢复处理和完成之间切换时，图标会就地变化，不会重建终端或打断输入。未安装 lifecycle hook 时，Claude Code / Codex 启动后连续约 5 秒没有输入或输出，标签会停止旋转；再次输入或收到输出会恢复运行状态。已安装 hook 时始终以 Agent 的精确 lifecycle 为准，不会因静默推理而提前停止。等待输入只在 password、`[y/n]`、yes/no 或 Press Enter 提示停留约 1.5 秒后出现，输入任意内容即清除；Agent 完成后的未读圆点也会在用户继续输入后清除。外观设置可开启 Dock 运行动画；错误标红默认开启，点击 Dock 图标会跳到失败标签并清除当前提示。

安装 `aster` CLI 后，可以包装一次性任务或直接设置当前标签徽章：

```bash
aster watch make deploy
aster watch -q cargo test
aster tab badge --kind awaiting-input
aster tab badge --clear
```

`watch` 保留被包装命令的原退出码；`-q` 只关闭本次完成通知，不关闭进度和徽章。

终端应用可使用 OSC 9、OSC 777 或 OSC 99 发送 macOS 通知。OSC 99 支持独立标题/正文、紧急级别、base64、分片和同 ID 替换。Shell 设置可分别控制：成功、错误与 watch 完成通知，Shell Controlled，总在前台/仅未聚焦标签/关闭的前台策略，Dock 弹跳，错误退出 beep、BEL，以及错误/完成/应用通知是否附带声音。系统权限行显示 macOS 当前状态并可打开系统设置。

标题权限位于“设置 → 高级”：Shell Controlled 控制 OSC 0/1/2 是否能修改标题；“标题报告”控制程序能否读取标题，默认关闭。OSC 52 剪贴板权限与安全键盘输入仍分别位于“控制”。

## 查找与命令面板

按 `⌘F` 在当前终端的完整滚动缓冲区中查找，并用上下箭头跳转；普通文本、区分大小写和正则选项都由 Ghostty 内核执行。“全局查找”继续搜索所有终端、编辑器与预览 Pane；命令 Outline 使用稳定缓冲锚点精确跳转，历史所在 page 已被 scrollback 裁剪时会显示为不可跳转。

按 `⇧⌘O` 打开 Open Quickly，顶部标签条可在“全部 / 已打开 / 最近 / 文件夹 / SSH / Agents / 当前 / Recipes”中过滤（`⌘J` 直接打开“当前”页）；支持模糊搜索，结果行带类型图标、相对时间和类型徽章，多类型视图按分组显示小节标题。结果会直接跳到 Pane、打开常用目录、预填 SSH、恢复 Agent 历史或打开 Recipe。“当前”页还会显示各 Pane 正在运行的前台命令，并追加“提示词”分组列出最近会话的输入：有 Agent 正在运行时写回对应 Pane，没有运行 Codex、Claude Code 等 Agent CLI 时也可选择 Prompt，内容会直接预填到当前终端且不自动回车。列表内用 `↑`/`↓` 选择、`↩` 跳转、`⌘1`–`⌘9` 快速选中对应行，`⌘K` 或底部“操作”按钮弹出选中行的更多动作（关闭标签、Fork 会话、在 Finder 中显示、复制提示词等）。按住 `⌘` 会在顶部标签和前九条结果上显示快捷键：`⌘0/W/R/Z/S/G/J/E` 分别切换全部、已打开、最近、文件夹、SSH、智能体、当前和 Recipes，松开后提示自动隐藏。按 `Esc`、切换到其他应用，或在 Aster 窗口的浮层外部（包括标题栏）用任意鼠标键点击，都会立即关闭面板。按 `⇧⌘P` 打开的命令面板样式与 Open Quickly 同源，还覆盖新窗口、Pin、两种画中画、详情、Agent、分屏、文件、查找、模式与关闭动作，按 Pane / Window / Application 作用域分组显示小节标题；固定绑定快捷键的常用命令（新建标签页、拆分、缩放拆分等）在行尾显示按键提示。

Open Quickly 打开后输入焦点会直接落在搜索框，无需再点击即可输入；点击搜索框也不会触发外部点击关闭。Open Quickly 中的 Agents 分类在界面显示为“智能体”。浮层打开、关闭和顶部分类切换不会重建终端工作区；结果较多时仍可直接输入搜索，既有结果行会复用，避免点击时出现明显停顿。

命令面板、Open Quickly、全局查找和 Agent 历史都可以随时按 `Esc` 关闭；即使刚刚点击了结果、按钮、会话内容或后方终端，也不要求先把焦点移回搜索框。没有打开这些浮层时，`Esc` 交给当前终端。

“显示 → 详情面板”包含 Info、Outline、Git、Files 和 History 五页，顶部 icon 页签切换：未选中页签保持统一的图标宽度与间距，鼠标悬停会有淡底色反馈，点击后当前页签平滑展开出名称（系统开启“减弱动态效果”时直接切换）。详情面板展开时，右上角折叠图标一直显示；面板收起后，同一位置的标题栏展开图标只在鼠标位于标题栏时显示。为了让关闭动作更自然，收起完成时图标会在原位短暂停留，再在鼠标已离开标题栏时淡出，整个过程不会左右跳动或闪出第二颗图标。也可通过“显示”菜单或命令面板切换。拖动中央内容与详情面板之间的分隔线可在 240...480pt 内调宽，双击恢复默认 278pt；拖动不会收起详情面板。展开与收起带 0.18 秒的整块折叠/展开过渡（系统开启“减弱动态效果”时直接切换）：详情内容由 Panel 边界同步裁剪，中央区域同时补位，不会先滑走内容再折叠空壳；终端只在显隐终态切换时调整一次。展开、收起和页签切换不会重建终端、侧栏或已经加载的页面，终端输入焦点保持不变；收起时会停止尚未完成的检查，但保留已完成结果与 Files 的搜索、排序和展开状态。Info 页显示工作目录、动作链接（复制路径、在 Finder 显示、在已安装的编辑器中打开）、以当前 shell 为根的本机进程树与去重监听端口；只有 lifecycle 集成精确绑定当前 Pane 的 provider/session 时才显示会话复制、历史与 Branch 动作。Info 当前可见时约每三秒更新一次，非终端 Pane 或检查失败会明确说明，不会冒充为空结果。Outline 页是“时间线”页：上半部实时显示运行中、成功或失败的终端命令（需要 Shell Integration，含状态与相对时间，点击或右键 Jump 跳回原位置，并可复制文本），也显示精确绑定会话的 Agent 提示词，以及 Markdown、HTML、JSON、YAML、TOML、Diff 与 JSONL transcript 的文档结构；连续编辑会自动合并刷新，点击条目跳到对应行。下半部是本项目过去的会话记录（需在设置中开启 Session Recording）：按会话列出时间线——命令与退出码、输出（可展开看正文）、Agent 工具调用、文件读写、git 快照；来自 Agent 自己 transcript 的补录条目会单独标注，区别于终端实测。History 页是本项目的记忆（Memory）：固定（PINNED）条目置顶成组，其余按时间倒序；每条显示标题、摘要与“类型 · 提炼来源 · 时间”副标题。搜索、固定、禁用与删除在 Memory 浏览器中进行，页头提供入口与手动刷新。Git 页显示分支、+/− 统计与按暂存状态分组的变更。Commit 和编辑器控件都以“主动作 + 下拉箭头”共用一块圆角背景呈现；下拉仍有独立悬停和按压反馈。Commit 下拉提供 Push、Pull、Fetch、Merge… 和 Rebase…，选择后立即把对应命令预填到终端；Merge 与 Rebase 气泡，右侧的尖角指向对应的那一行；按 `Esc`、点击气泡外或切走 Git 页即可关闭。**所有仓库写操作都只把命令预填到终端输入行**，包括 Commit、暂存、Push/Pull/Fetch 与 Merge/Rebase：确认后由你回车执行，Aster 不在后台跑写命令。分支名与文件路径会按 Shell 规则转义。Files 页以当前 CWD 为根显示有界目录树，目录与文件图标使用压低饱和度的淡强调色、文件名保持默认前景；目录首次加载时默认收起，只显示顶层文件与目录；点击箭头或双击目录在树内展开/折叠，Find 搜索会临时展开匹配路径。Find 旁可切换目录优先排序，以及用眼睛图标决定是否**一并列出**隐藏文件（默认不包含，开启后普通文件与 `.gitignore`、`.build` 等隐藏项一起显示，不是只显示隐藏项；隐藏目录只显示名称、不展开其内部海量文件）。Files 右键菜单固定为 Open、Open in Aster（当前 Pane、新标签、新窗口和四向分屏）、新建/重命名/废纸篓、路径复制和 Finder；目录展开仍只由 chevron 或双击负责。**Git 与 Files 两页的文件都要双击才打开**——单击只用于浏览，不会因为误触在工作区多开一个 Pane；Git 页也可以用行尾的编辑器图标或预览图标。大目录只渲染当前可见行，搜索输入不会重建搜索框。Info、Git 和 Files 按当前选中页独立加载，互不等待。在终端中切换目录时，旧树会保留到新目录读取完成后平滑替换，终端输入焦点不会移到详情面板。

在不同 Pane 之间切换时，详情面板会保留当前内容，等新 Pane 的 Info、Outline、Git 或 Files 结果准备好后一次替换，不再先清空列表。刷新期间旧内容不可点击；检查超过很短时间时，右上角会显示“正在更新…”提示，完成后自动恢复操作。

详情面板关闭时，只有右侧 Panel 本身保留折叠动画；中央终端区一次补到最终宽度，不会被显示层再次拉伸，动画末帧也不会因临时分隔线再跳 1pt。右上角始终是同一颗固定位置的图标，关闭过程不移除、不替换；Panel 完全关闭后再停留 650ms，鼠标已离开标题栏时才淡出。

## Recipes 与会话恢复

“显示”菜单可把当前标签保存成 `.asterrecipe`，或重新打开 Recipe。Recipe 可保存 tab/window 作用域、完整嵌套分屏及比例、Pane 类型、目录、文件、可选命令和内容级别，不保存 PID、令牌或文件描述符。每次打开都会生成新的 Pane 身份，因此同一 Recipe 可安全重复使用。外部 Recipe 必须是受大小限制的普通文件，引用的编辑资源也有累计预算。

外部 Recipe 的命令默认先完整列出全部命令并确认，不会隐藏第 21 条及后续内容；可在“设置 → Recipes”选择从不重放、一次确认、逐条确认或仅对相同 SHA-256 内容信任。信任跟随文件内容而非路径，文件修改后必须重新确认。“逐条确认”会在每条命令真正写入终端前提供运行、跳过和停止选项。命令只在 Shell Integration 已就绪且停在空闲 Prompt 时串行发送，上一条收到完成标记后才发送下一条。

“设置 → Shell → 会话恢复”决定退出并重新打开 Aster 时，各终端 Pane 里正在运行的东西如何回来：

- **恢复复用器会话**：快照时前台是 `tmux` / `screen`，重启后在首个 Prompt 自动执行 `tmux attach -t <会话>` 或 `screen -r <会话>`（解析不出会话名时用无参附着）。
- **恢复 Code Agent 会话**：Claude / Codex / OpenCode 以原生 `--resume` 重连（与“智能体”页是同一开关）。
- **终端恢复协议（OSC 88）**：程序可以声明自己重启后应如何被拉起。`printf '\e]88;query\a'` 会收到 `\e]88;supported;v=1\a`；`printf '\e]88;restart=nvim .\a'` 声明恢复命令，`\e]88;clear\a` 撤销。声明只写入工作区快照，恢复时作为普通输入发送，不会被解释执行。
- **恢复时重新运行进程**：“不重启 / 仅白名单内 / 所有运行中的进程”。白名单按逗号分隔、按命令前缀匹配（`npm run` 匹配 `npm run dev`）。

优先级为 OSC 88 声明 > 复用器 > 普通进程；绑定了 Agent 会话的 Pane 只走 Agent 重连。恢复命令都在 Shell 首个 Prompt 出现时发送，用户在此之前输入任何内容即取消；开关在发送时读取，改完设置无需重新退出一次。

误关 Pane 或标签后按 `⇧⌘T` 可按最近关闭顺序逐个恢复。关闭历史跨正常退出和崩溃保留；正常退出会恢复主窗口和仍打开的附加窗口，连续崩溃三次会绕过可能损坏的快照并打开干净 Shell。可序列化布局会恢复，但不会持久化 PID、文件描述符或只读等临时状态。

## CLI 与深链

在“设置 → Shell → Aster CLI”安装 `aster` 后，可从 Shell 控制工作区：

```bash
aster open ~/project --title API
aster view README.md --right
aster edit Sources/App.swift --new-window
aster jump project
aster learn ~/project
aster ignore ~/Downloads
aster pane capture --lines 100 --format json
aster pane send-text 'npm test\n'
aster pane run -- npm test
aster pane exec --format json -- git status --short
```

`open/view/edit/jump/learn/ignore/capture` 是只读或工作区动作；`pane send/run/exec` 必须先在“设置 → 控制 → IPC”开启“允许发送输入”，SSH 或 sudo 等敏感会话还需单独开启“允许敏感会话”。`aster://learn?...` 深链只处理有界目录学习请求；`ssh://` 只预填命令，不自动执行。

安装的 `aster` 是指向 Aster.app 内 `aster-cli` 的符号链接：优先放在 `/usr/local/bin`，不可写时放 `~/.local/bin`（请确认它在 PATH 里）。旧版本写入的 sh 脚本会被自动替换；如果那个位置已经有一个不是 Aster 安装的 `aster`，安装会拒绝覆盖并提示。CLI 通过当前用户专属的本地 socket（默认 `~/Library/Application Support/Aster/Control/aster.sock`，仅本人可连；HOME 路径过长时回退到 `$TMPDIR/aster-control.sock`）与应用通信，不监听网络端口。Aster 的终端里会注入 `ASTER_SOCKET_PATH` 指向实际路径；要让应用监听别处，可在启动 Aster 前设置 `ASTER_CONTROL_SOCKET_PATH`（绝对路径），CLI 侧也可用 `--socket <path>` 或 `ASTER_SOCKET_PATH` 显式指定；Aster 没有运行时它会在后台拉起应用并等待最多 5 秒，仍连不上则以退出码 69 结束。运行 `aster --help` 查看完整语法，`aster --version` 查看版本。

在 Aster 的终端里，`aster` 还能查看和控制其它 pane 与 Agent：

```bash
aster session snapshot                       # 所有窗口 / 标签 / pane
aster agent list                             # 正在运行的 Agent 及状态
aster agent read w1:p2 --lines 40            # 读某个 Agent 的屏幕
aster agent prompt w1:p2 "跑一下测试" --wait  # 提交 prompt 并等它空闲
aster pane read --current --source recent
aster pane send-text --pane w1:p3 'npm test' --enter
aster pane wait-output w1:p3 --match "passed" --timeout 60000
aster events subscribe --kind pane.agent_status_changed
aster notification show "构建完成" --body "全部通过"
```

pane 与 Agent 用短 ID 引用（`w1` 窗口、`w1:t2` 标签、`w1:p5` pane），也可用 Agent 名或 `--current`（当前 pane，来自环境变量 `ASTER_PANE_ID`）。`agent`、`events`、`notification` 命令只在 Aster 自己的终端里可用（环境变量 `ASTER_ENV=1`），在别的终端里需要显式加 `--allow-outside`。写入类命令与 `pane send/run/exec` 受同一套 IPC 开关约束；`--json` 输出原始结果，出错时 stderr 打印 `{"code":"…","message":"…"}` 并以退出码 1 结束。

## Working with Agents

Aster 支持 Claude Code、Codex、OpenCode、Cursor CLI、Kimi Code、Pi、omp 和 Grok Build。在“设置 → 智能体”中，每个 provider 会显示图标与检测到的 CLI 绝对路径；从 Finder 或 Dock 启动 Aster 时，也会识别 `~/.local/bin`、Homebrew 及常见 Node 版本管理器里的安装。右侧“已安装 / 关闭”和开关专指 Aster 受管 lifecycle 集成，与 CLI 路径是独立状态；展开一行后可另行控制它是否出现在快速启动入口，并为 wrapper、环境配置或自定义可执行文件设置结构化启动命令。安装和卸载只改动带 Aster 标识的 hook/plugin；用户自己的配置保持不变，变更后应重启对应 Agent。Grok Build 的用户级 hook 写在 `~/.claude/settings.json`（Grok 把它当 Claude 兼容层读取），与 Claude Code 的 Aster 条目并排、互不覆盖；两边的 hook 会先确认调用方再上报状态，避免把 Grok 标签标成 Claude。Grok 首次在某个项目跑 hook 时可能要 `/hooks-trust`。Grok 会话暂时不会出现在 Agent 历史浮层或 Open Quickly。

- lifecycle hook 把 `processing / idle / awaiting-input` 归一到所属 PTY，驱动标签徽章、完成/等待通知和“处理期间阻止睡眠”。不会读取或保存 prompt 正文。
- “Shell”菜单对齐 Otty 的完整结构：顶部是“重命名标签页…”“设置标签页前缀…”（共用同一原生对话框，后者预选动态前缀模式）与“清屏”（`⌘K`）；随后是围绕当前工作目录的“拷贝路径”“在访达中显示”“打开方式”（无可靠 CWD 时置灰）；中段保留 Vi/Mark/Hint、只读模式与 Composer；底部是“Git”子菜单（图形客户端入口 + Commit/Push/Pull/Fetch/Merge…/Rebase…，全部只预填命令到终端，由你回车执行）与“通知与权限…”（跳到设置的 Shell 分类）。“打开方式”与“Git”和窗口标题胶囊弹层显示完全相同的条目。
- 打开“Shell”菜单时，Aster 会根据当前聚焦 Pane 显示 `Codex`、`Claude` 等对应的 Agent 子菜单；切换分屏后菜单随焦点更新，不会操作同一标签里的其它 Agent。菜单展开后，Fork 动作会固定作用于当时的工作区，不会因设置页或其它窗口切换到前台而失效或落到别处。在“设置 → 智能体”安装对应 lifecycle 集成并重启 Agent 后，会话会自动关联，可拷贝会话 ID、查看会话历史，或 Fork 到上下左右分屏、新标签页、新窗口。Agent 子菜单的“查看会话历史”只显示当前项目的会话（优先按已关联会话的项目归属判定，尚未关联时按该 Pane 的工作目录）；要浏览全部项目的历史，请使用命令面板（`⇧⌘P`）里的“Agent 历史”。Codex 首次加载新 hook 时还需运行 `/hooks` 审核并信任 Aster 条目；安装器会迁移旧版 Aster 遗留的非法顶层 `hooks` 布尔配置。尚未收到可信会话 ID 时，复制与 Fork 会保持禁用。
- Agent 历史浮层（Agent 子菜单“查看会话历史”按当前项目打开；命令面板“Agent 历史”显示全部）与 Open Quickly 可搜索已知 provider 的本机会话记录，并使用 provider 原生命令 Resume 或 Fork；不支持 Fork 的 provider 会明确拒绝。在 Agent 历史里按 `↩` 或点“打开”，会像 Otty 一样把该会话作为新标签打开：左侧 TABS 增加一项（标签名即会话标题），右侧只读渲染完整 transcript：你的消息显示为浅色卡片、Agent 回复按 Markdown 渲染，连续的工具调用折叠成一行摘要（如「Claude · 30×Bash, 26×Edit」，点击展开）；页头显示标题、会话文件与项目归属，并提供 Resume / Fork。超长会话按单条与总量上限截断并明确标注；同一会话重复打开只会选中已有标签。
- Composer 支持多行草稿、普通文件附件、固定/浮动与取消；发送时使用 bracketed paste，仍服从只读和粘贴保护。Prompt Queue 只按 lifecycle hook 的 `idle` 自动派发，`processing` 与 `awaiting-input` 都只排队；未安装 hook 时不自动发送，每一项都由你点击左侧发送图标提交。
- **让 Agent 自己操作 Aster（skill）**：Aster 附带一份 skill 文档（`aster --skill` 可打印），教 Claude Code / Codex 用 `aster` 命令读旁边 pane 的输出、启动或等待另一个 Agent、发送按键与通知。在“设置 → 智能体”点“安装 Aster skill”会把它复制到 `~/.claude/skills/aster` 或 `~/.codex/skills/aster`，并写入版本标记；Aster 升级后设置页会提示“需要更新”。只会接管带 Aster 标记的目录：你自己写的同名 skill 或符号链接不会被覆盖，卸载也只删 Aster 装的那份。skill 里的写入动作（提交 prompt、发送文本、聚焦）同样需要“设置 → 控制 → IPC 允许发送输入”，没开时 Agent 会收到 `write_not_allowed` 并转而请你手动操作。skill 只在 Aster 的终端里生效（`ASTER_ENV=1`），Agent 在别的终端里不会误用它。
- Send to Chat 可接收终端选区、当前可见 transcript 或文件上下文。上下文被包在 `untrusted-context` 中，移除终端控制字符、遮盖常见密钥并执行 128 KiB 总预算；Aster 不声称能识别所有业务敏感信息，发送前仍应复核。终端发送面板会以普通键入预填目标 Agent 输入框，最终提交始终由你决定。

## 项目记忆（Session Memory）

Aster 可以把终端里发生的事情记下来，让下一个 Agent 直接查到项目过去的工作过程 —— 换 Agent 不用重新解释一遍历史。**默认关闭**，要在“设置 → 智能体 → Session Memory 记录”里主动开启。

- **记录模式**有三种：`关闭`、`记录中`、`隐身`。`隐身`和`关闭`一样零落盘，区别只是语义上表示“这一段临时不记”。开启后记录的是：命令、退出码、命令输出摘录、当前目录、Agent 状态与 git 分支/commit；命令输出正文另存为文件，主库只留摘录。没敲过任何命令、也没有 Agent 参与的空会话不会被记录，History 列表里也不会出现。
- **排除目录**和**排除命令**在事件产生的那一刻就拦掉，不是先记下来再删。命中排除的命令，它的输出也一并不记。写入前还会统一遮盖常见密钥（与 Send to Chat 同一套规则）。此外有一组**内置排除基线**始终生效、无需配置也无法移除：`~/.ssh`、`~/.gnupg`、`~/.aws`、`~/.kube`、`~/.password-store` 目录，以及 `op`、`vault`、`pass`、`gpg`、`security` 命令；你自己的排除列表只会在基线之上追加。
- 数据全部在本机 `~/Library/Application Support/Aster/Memory/`，目录 `0700`、文件 `0600`。设置里可以直接查看已用空间、打开目录，或清空全部记录。这条通道与诊断日志完全独立，两边的脱敏策略不同，不共享任何文件。
- **Memory 提炼**：会话结束后把事件流提炼成可复用的结论（问题、根因、失败尝试、最终方案）。shell 自己退出（`exit`）和关闭标签/Pane 都算会话结束；直接退出应用或应用意外崩溃时来不及提炼的会话，会在下次启动 Aster 时自动补上，不会丢。本地规则式提炼始终启用、不联网；“使用 CLI Agent 提炼”是可选增强，会调用你本机已装的 Agent CLI，**这会把会话摘要发送到该 Agent 的云端**，因此默认关闭，首次开启需要确认，并且可以点“查看将发送的内容”逐字预览。CLI 不可用、超时或解析失败时自动回落到规则式，已记录的事实不受影响。
- **查看历史**：右侧详情面板 Outline 页的下半部按会话列出时间线 —— 命令与退出码、输出（可展开看正文）、Agent 工具调用、文件读写、git 快照。来自 Agent 自己 transcript 的补录条目会单独标注，区别于终端实测。History 页则显示本项目已提炼的记忆（Memory）概览，固定条目置顶，页头可打开 Memory 浏览器管理。
- **Task 与 Memory 管理**：命令面板（`⇧⌘P`）提供“浏览 Session Memory”“新建 Task”“把当前会话归入 Task”“继续 Task”。一个 Task 可以关联多个 Agent 的多次会话。Memory 浏览器是**独立的面板窗口**，不是工作区里的浮层——你可以让它一直开着，一边看历史结论一边在终端里继续敲；关掉它焦点自然回到工作区。面板里可以搜索、查看来源回链、**固定**、禁用或删除某条 Memory；被禁用的 Memory 对 Agent 检索完全不可见。
- **固定关键结论**：重要的架构决策、编码约定可以在浏览器里点“固定”。固定后的 Memory 会**无条件**随项目上下文交给 Agent，不参与检索排名——关键事实不该赌它每次都能被搜出来。
- **记录会自动瘦身**：超过 90 天的原始命令记录（事件与输出正文）会在会话结束时自动清理；已提炼的 Memory 和会话摘要**永久保留**。过程可丢，结论长存。
- **Agent 拿到了什么**：同一面板的“Context 记录”列出每次 Agent 通过 MCP 查询的时间、查询内容、给出了几条 Memory 和大致 token 量。

### 让 Agent 查到项目记忆（MCP）

Aster 附带一个本地 MCP server `aster-memory-mcp`，任何支持 MCP 的 Agent 都能用它查询同一份项目记忆。它以**只读**方式打开数据库，Aster 没运行时也能查。

提供的工具：`search_memory`（搜索历史 Memory 与命令）、`get_project_context`（项目概要，固定的 Memory 永远排在最前）、`get_session`（某次会话的完整时间线）、`get_related_history`（按文件或关键词找相关历史）、`get_task`（Task 详情或列表）、`get_recent_commands`。

检索有两条内建保护：查询词太笼统、命中毫无区分度时返回空而不是把垃圾塞给 Agent；当前项目查不到时自动放宽到其它项目，命中会明确标注“来自其它项目”。所有交给 Agent 的历史文本都带“非指令”声明并做了结构消毒，历史输出里的指令形状文本不会被当成命令执行。

注册入口在“设置 → 智能体 → 项目记忆 MCP”，排在记录与提炼两组之后：先决定记不记、怎么提炼，才轮到交给谁用。

- 顶部显示当前项目目录（取自最近活动工作区窗口的当前标签），MCP 按项目注册。
- **Claude Code** 一键写入该项目的 `.mcp.json`。只管理 `aster-memory` 这一项，你已有的其它 server 原样保留；已注册且路径正确时按钮显示“已安装”并禁用，路径过期时变成“修复路径”，另有“移除”。
- **Codex** 只给出需要粘贴的配置片段和复制按钮，Aster **不会**替你修改 `~/.codex/config.toml`。
- 如果读取 `.mcp.json` 失败（权限、符号链接、文件过大或 JSON 损坏），这里会如实显示原因并禁用安装按钮，而不是假装“未安装”让你再撞一次同样的错。

## 十类设置

设置使用唯一独立窗口，默认内容尺寸为 `700 × 460 pt`；打开后主工作区保持原尺寸、原内容并完整可见，运行中的终端不会中断。设置保持打开时，主窗口仍可切换或创建 Tab、操作和拆分 Pane，变化会立即显示。拖动设置窗口顶部可移动窗口；**窗口四周都可以拖动调整尺寸**，最窄 `700 pt`、最矮 `460 pt`；调整后的宽度和高度都会被记住，下次打开继续使用（换到更小的屏幕时自动收回到屏幕内）。黄色最小化按钮禁用，点击红灯只关闭设置窗口。Dock 右键菜单不提供“打开设置…”入口，也不会把设置窗口列为“Aster 设置”。

设置内容现在由 Aster 内置网页渲染，左侧保持通用、Shell、控制、编辑器、智能体、视图、外观、Recipes、快捷键和高级十类导航。顶部搜索会在全部分类中查找设置项；点击结果会跳到对应分类。开关、下拉、文本、颜色和滑杆会立即保存，错误值会显示提示并恢复当前真值。设置页面本身不联网，也不会打开 Otty 或其它产品页面；只有「更新 → 现在检查」和「控制 → 补全数据库 → 立即更新」两个按钮会由 Aster 主程序发起网络请求。

- “高级 → 配置文件”可打开 `~/Library/Application Support/Aster/settings.json`；修改后点击“重新加载配置”。文件格式版本为 3，导入仍兼容旧版 Aster JSON。
- Windows 文本渲染会显示“Windows”标记；Aster for macOS 会保留该值供配置往返，但不会应用，也不能在当前平台编辑。
- “快捷键”中点击键帽后直接按新的组合键；修改会更新 AppKit 菜单快捷键并跨启动保留，`Esc` 取消本次录制。
- “Recipes”会列出 `~/Library/Application Support/Aster/Recipes` 下的 `.asterrecipe`，可在 Finder 中定位或打开目录。
- 设置页保留系统动作的真实失败信息：例如 Shell 集成、Agent 集成、CLI 安装或配置导入失败时，不会把开关伪装成成功。

左侧导航固定为 `200 pt` 并延伸到窗口顶部；窗口拉宽时，右侧单列内容自动填满新增空间，卡片和控件随可用宽度调整，不会在右侧留下空白。左上角搜索使用中性灰背景，打开设置时不会自动获得输入焦点；点击搜索框可跨十类设置搜索标签与说明，选择结果会跳到对应分类和字段。右侧内容按「分组标题 + 圆角卡片」组织并从页面顶部开始，内容较长时可使用滚动条。切换分类只更换右侧内容，开关、滑杆、步进器与输入框都是就地响应；收到 Swift 真值快照后会保留当前分类。外观页的“左侧 Panel 宽度”和“右侧 Panel 宽度”编辑最近活动的工作区窗口。

- **通用**：界面语言、启动行为、窗口关闭行为、关闭标签页 / 窗口 / 面板的确认策略，以及系统集成（注册为 ssh:// 链接的默认终端、常用外部应用的默认终端、Finder「在 Aster 中打开」服务、完全磁盘访问入口），以及软件更新（自动检查、自动下载安装、稳定/预览通道、立即检查）。
- **Shell**：按 Otty 同构排列——新窗口/新标签页/新分屏的工作目录、Shell/SSH 集成、Aster CLI（安装命令、省略 `aster` 前缀、覆盖已有命令、自定义别名）、常用文件夹（自动记录、管理已跟踪/已忽略、Zoxide 同步）、会话恢复（复用器、Code Agent、终端恢复协议、恢复进程三档：不重启/仅白名单内/所有运行中的进程）、声音（终端响铃、出错蜂鸣）、通知（系统权限状态、应用/完成/出错/watch 通知、前台策略、按类别选择的通知声音、Dock 图标跳动——持续跳到切回 Aster）和终端标识。`TERM` 通过下拉选择，`auto` 优先使用应用内置的 `xterm-ghostty`（能力与终端引擎一致），缺少条目时回退到兼容的 `xterm-256color`；选择“自定义…”后可填写本机真实安装的 terminfo 名称。
- **控制**：与 Otty 相同，严格按自动补全、选择、滚动、打开方式、链接协议、键盘、鼠标、安全输入、剪贴板九组排列；包含 inline suggestion、Option/Meta、VT100 keypad、TUI 鼠标绕过、复制清理、危险粘贴、链接 scheme/安全例外、首尾滚动和安全输入指示。
- **编辑器**：自动换行、行号、不可见字符、Tab 宽度、滚动越过末尾、Vim 按键与富文档预览。
- **智能体**：八类 Agent（含 Grok Build）的启用状态、结构化启动命令、集成安装/卸载、标签徽章、通知与运行选项。
- **视图**：对齐 Otty 的四组。「标签页与标题定制」按项（别名 / 图标 / 标题各一张规则列表）或按项目（一个项目同时设三项）排列规则；每条规则由路径、命令、Agent、SSH 主机、文件等条件（全部成立才命中，无条件即所有标签页）加上项目别名、图标（61 个内置图标或 emoji，可着色）和标题模板组成，模板支持 `${alias}`、`${cwd}`、`${folder}`、`${user}`、`${host}`、`${agent}`、`${branch}`、`${command}`、`${title}`、`${shell}`、`${index}`、`${file}`，`${title|folder|'Shell'}` 取第一个有值的；规则标题优先级低于手动固定名、高于自动标题。「标签页图标与角标」选择图标与角标合并（共用一个指示位，有状态时角标接管）或分开（图标在左、角标在右并隐藏 shell 名），以及命令完成 / 失败 / 等待输入三种角标开关。「网页窗格」控制是否把 cookie 写盘（只影响之后新开的窗格）并可一键清除全部浏览数据。「详情面板」用拖动排序和开关决定信息 / 大纲 / Git / 文件 / 记忆哪些显示、按什么顺序，还可以「添加视图」：在面板内运行终端程序（如 `lazydocker`，命令与目录支持 `${cwd}`、`${pid}` 等变量，目录留空时使用 `~/.config/aster/views/<名称>`）或加载一个网页（可按移动版请求）。
- **外观**：当前工作区左右 Panel 宽度、标签位置与自动隐藏、窗口尺寸、Dock 任务状态、浅深色主题、主题编辑/导入、文本样式、字体来源与回退、光标颜色/样式/闪烁/动画。
- **Recipes**：命令重放与按内容信任策略；外部命令必须按所选策略确认。
- **快捷键**：查看内置快捷键。
- **高级**：自动进度命令、标题修改/读取权限、导入/导出 JSON 配置、重置和运行内核信息。

全局设置可随配置保存与导出；左右 Panel 宽度属于工作区窗口，仅随对应工作区保存，不包含在配置导入/导出中。通知最终是否显示还取决于 macOS“系统设置 → 通知”中的应用权限和横幅样式。

## 软件更新

Aster 默认**每天在后台检查一次**官方更新源。为了让更新真正做到开箱即用，这个开关首次启动时就是打开的，不会先弹框询问你——如果你不想要，随时到「设置 → 通用 → 更新」关掉「自动检查更新」。

这一组一共四项：

- **自动检查更新**：关掉之后只能手动点「现在检查」。
- **自动下载并安装**：默认关闭。打开后新版本会在后台静默下载，等你退出 Aster 时自动完成安装，不会打断正在运行的终端。之所以不默认开启，是因为终端里常有跑很久的命令，静默重启的代价太大。
- **更新通道**：稳定版只接收正式发布；预览版会更早收到测试构建，也更可能遇到问题。注意从预览版切回稳定版**不会把你降级**——你会停在当前的预览版上，直到稳定分支的版本追上它。
- **现在检查**：与 Aster 菜单里的「检查更新…」完全等价。按钮左边的圆点显示当前状态：灰色是尚未检查或正在检查，绿色是已是最新，橙色是发现了新版本，红色是检查失败。

更新只会请求 Aster 的官方更新源，下载的安装包要同时通过 Aster 的签名校验和 macOS 的公证校验才会被安装。整个过程不会发送任何使用数据或系统信息。

如果这一组设置整体是灰的、并显示「此构建未启用自动更新」，说明你运行的是从源码构建的开发版本，它没有配置更新源。请从项目发布页下载正式版本。

> 从 0.4.1 或更早版本升级：那些版本还不包含更新组件，收不到自动更新，需要手动下载一次新版 DMG。此后就能自动更新了。

## 常见问题

### 为什么窗口缩窄后 Panel 看起来小于设置值？

Aster 会优先给中央内容保留可操作空间，窗口不足时临时压缩右栏、再压缩左栏。这不会覆盖保存值；把窗口拉宽后会自动恢复。若要隐藏某一栏，请使用标签栏折叠或详情面板开关，不能通过拖动分隔线隐藏。

### `vim` 或 `top` 显示不正常？

确认“设置 → Shell → 终端标识 → TERM”为 `auto`（优先使用内置 `xterm-ghostty`，或本机真实安装的 terminfo 名称），并开启“控制 → 允许鼠标报告”。无效的自定义名称会在 Pane 中显示启动告警并自动回退到 `xterm-256color`。SSH 到没有 `xterm-ghostty` 条目的远端主机时，可在远端安装该条目，或临时执行 `TERM=xterm-256color ssh …`。

### 输入 `exit` 后怎么办？

该 Pane 会保留最后画面，并显示“Shell 已退出”卡片；点击“重新启动 Shell”可在同一个 Pane 创建全新的 Shell。卡片外的历史内容仍可选择和复制。Aster 不会在你主动输入 `exit` 后自动重启，避免违背你的退出意图。

如果 Shell 以非零状态码退出、被信号终止或 PTY 连接异常，卡片会显示对应原因。点击“重新启动 Shell”同样会创建全新的 PTY，不复用已经结束的进程通道；需要排查时可从“帮助 → 反馈问题…”打开本机日志文件夹。

### Recipe 会自动执行命令吗？

取决于“设置 → Recipes”的重放模式。默认会先显示命令预览并确认；选择“从不”时只恢复布局，选择信任时也只信任当前 SHA-256 内容，文件修改后会再次询问。命令按空闲 Prompt 串行重放，不会直接交给独立 `/bin/sh` 执行。

### 关闭编辑器时会丢内容吗？

不会直接丢弃。存在未保存内容时，关闭 Pane、标签或退出应用都会询问“保存 / 不保存 / 取消”；保存失败会阻止关闭。

## 外观主题

### 选择主题

打开“设置 → 外观”，主题按“明亮主题”和“黑暗主题”分成两个完整区域（每行四张卡片，窗口拉宽时卡片同步变大）。Aster 内置与 Otty 1.3.1 对齐的 9 个明亮主题和 15 个黑暗主题；选择后，无需关闭设置窗口，工作区和已经打开的终端会立即更新，并自动切换到该主题对应的明亮或黑暗外观。选择黑暗主题时也会自动启用独立黑暗主题。

需要快速比较时，使用“显示 → 主题”。这个选择器同时列出全部 9 个明亮和 15 个黑暗主题，并与参考产品一样支持搜索；按上/下方向键或把鼠标移到某一行，左侧 Tabs Sidebar、标题栏，以及容纳中央 Pane 与右侧 Inspector 的 Container 会立即预览。点击主题或按回车保存并切换到对应明暗外观；按 `Esc`、点到面板外或切到其它应用会取消，并恢复打开选择器前的主题。

Glass Light 与 Glass Dark 会保留主题的真实透明值，由 macOS 原生材质显示桌面内容；截图里看到的灰度只是当时桌面与材质合成的结果，不会被保存成固定背景色。所有分屏会同时切换，不会因活动状态出现一边黑、一边仍是旧主题。Floating Card、Nord、Pink、Monokai Classic 等主题会同时使用各自的光标文字色和选区前景/背景，不再用通用近似色替代。9 套浅色主题的窗口、Container、左侧 Sidebar、标签栏、标签、终端、Inspector、光标、选区和 ANSI 色都直接采用“详情”中显示的最终色值；右侧 Inspector 与中央 Pane 共用一张 Container 卡片，不会再叠加第二层 Sidebar 材质。浅色主题没有单独定义选区时，默认使用 30% 透明的终端前景色。

暗色主题同样会完整作用于 Pane 工具栏、查找栏、Tabs Sidebar 与 Inspector。Tokyo Night、Dracula 等只声明终端颜色的主题，会从各自终端背景派生稍亮的 Sidebar，而不是全部显示成同一种黑灰；File Pane 顶部也不会残留白色工具栏。

### 编辑主题颜色

1. 在主题库中点击主题卡即可选择；浅色卡写入浅色主题，深色卡写入深色主题。字体、光标颜色与透明度可在下方字段继续调整；光标颜色留空时跟随主题。自定义 `.astertheme` 可通过“导入主题”加入，主题文件夹可从同页直接打开。设置页自身只跟随系统明暗外观，不会被终端主题染色。
2. 主题详情先显示终端示例、前景/背景、ANSI 16 色和 Window、Panel、Tab、Cursor、Selection 等 token 胶囊。点击色块、ANSI 色或 token 胶囊会展开编辑器并定位到对应字段；也可点“编辑所选主题”展开全部参数。输入 `#RRGGBB` 或 `#RRGGBBAA` 后离开输入框即应用。修改颜色、ANSI 色或“字体系列 → 主题”中的字体时，Aster 保持当前主题名称和 ID，不会自动创建副本，而是在原主题配置末尾增加受管参数；只有明确点击“复制”才会创建新主题。
3. “恢复主题原始参数”清除当前主题的颜色、ANSI 与字体覆盖，不删除主题文件。能够映射到主题文件的参数会同步写入其 managed override 段；同步失败时 Aster 会保留已在应用内生效的参数并显示具体错误。

### 导入主题

点击“导入主题…”选择 `.astertheme` 文件。Aster 只接受 256 KiB 以内的普通文件，不读取符号链接、FIFO 或设备文件，并在加入主题库前检查名称和完整的 ANSI 16 色。点击“打开主题文件夹”会打开主题目录 `~/.config/aster/themes`，里面是内置主题、你编辑过的主题和导入的主题，全部是可以直接用编辑器修改的文本文件。首次启动时 Aster 会把安装包自带的 24 套主题复制到这里。Aster 不读取或写入 `~/.config/otty/themes`；`.astertheme` 与 `.ottytheme` 始终互不干涉。

### 文本与字体

“文本”区域可以调整字号、粗体、斜体、下划线、终端闪烁文字、连字、字体平滑和行高，修改会立即应用到已经打开的终端；菜单中的放大、缩小字号也会立即刷新当前终端。行高调整的是每行的网格高度和留白；无论终端使用普通绘制还是 GPU 加速，竖线光标都严格按当前字号绘制并在网格 cell 内上下居中，不会随字体额外 leading 或行高向上伸入上一行，也不会在普通 Shell 或 Agent 输入框内偏低。光标每帧都会先清除旧像素，切换样式或连续输入时不会留下整格残影。

“字体系列”区域按四个作用范围展示。字体名可直接输入；清空即取消该层设置并回到自动或继承。页面还提供“安装字体”和“打开字体文件夹”：

- “计算值”只读显示当前实际采用的普通、粗体、斜体和粗斜体字体（由 全局 → 主题 → 回退 解析得到）。系统字体显示为“系统等宽字体”。
- “全局”覆盖主题、全局优先：主字体取消设置时继续读取当前主题。“自动匹配粗细与样式”开启时不显示逐样式选择器；关闭后可为粗体、斜体、粗斜体单独指定字形。
- “主题”写入当前主题的覆盖参数：主字体写入 `font-mono` 候选栈首位（其余候选保留），逐样式字体写入主题的 `font-mono-bold` / `font-mono-italic` / `font-mono-bold-italic`。内置主题保持原名称和 ID，不会自动创建副本。“字体候选栈”一行仍可直接编辑完整候选列表。
- “回退”只在主字体缺少字符时补字，可分别配置普通、粗体、斜体和粗斜体；未填写的样式继承普通 fallback。Aster Nerd Symbols 始终优先保证 Powerline 和 Nerd 图标可见。

如果只设置普通字体并开启“自动匹配粗细与样式”，Aster 会从同一字体家族寻找粗体、斜体和粗斜体。找不到时会安全回退到普通字体。默认的 JetBrains Mono 2.304 随应用分发并在启动时注册，不要求系统预先安装。用户配置的其他字体未安装时，输入框原样保留该名字、不静默改写；终端最终改用 macOS 自带的 Menlo Regular，“计算值”页展示这一实际结果。注意 Nerd Fonts 补丁版的族名与原版不同（例如 `JetBrainsMono Nerd Font` 而非 `JetBrains Mono`），请以下拉列表中的实际名称为准。

### 光标

“光标”区域提供主题颜色或自定义颜色、光标下方文字颜色、不透明度、方块/竖线/下划线/空心方块、闪烁优先级和平滑动画。预览会同步显示当前组合。

闪烁优先级决定终端程序能否控制光标：

- “默认关闭 / 默认开启”只决定初始闪烁状态，vim、Claude Code、Codex 等程序之后仍可通过 DECSCUSR 开启或关闭闪烁，但不能覆盖你选择的方块、竖线、下划线或空心方块形状。
- “始终关闭 / 始终开启”连闪烁状态也固定为你的选择，忽略程序后续请求。

Codex、Claude Code 等 Agent 正在输出内容时，输入位置保留你的光标形状但暂停闪烁；进入等待输入或任务结束后恢复所选闪烁方式。切换 Pane 或窗口焦点时，非活动光标同样只停止闪烁，不会被替换成镂空方框。平滑动画仅处理同一行的短距离移动，并遵循 macOS“减少动态效果”设置。

### Dock 图标

卡片左侧的预览就是 Aster 的应用图标，也就是这些开关作用的 Dock 图标。“任务进行时旋转”只让图标中间的星芒匀速自转，圆角底板与 `>` 提示符保持不动；它会持续增加 CPU 与电量消耗，因此默认关闭。“出错时变红”把整块底板换成红色并加上 `!` 角标，点击 Dock 图标会跳到出错的标签。“收到通知时跳动”只在 Aster 不在前台且系统允许时触发，图标会一直跳到你切回 Aster 为止。这三个开关彼此独立。
