## 自动补全：命令之后的「下一步」

- `git clone` 完成后，空提示符上直接显示灰色的 `cd 仓库目录`，按 Tab 就进入刚克隆的仓库。
- 同样的推荐覆盖常见场景：`mkdir`、`git init`、`git worktree add`、各类脚手架（`cargo new`、`npm create`、`npx create-*`、`rails new`、`flutter create` 等）之后进入新目录；`tar`/`unzip` 解压后进入解压目录；`python -m venv`/`uv venv` 之后激活虚拟环境；`curl`/`wget` 下载压缩包后解压；`git commit` 之后 `git push`；`chmod +x` 之后运行脚本；`gcc`/`go build -o` 之后运行产物；`docker build -t` 之后 `docker run`。
- 只有目标目录或文件真实存在时才推荐；带 `&&`、`|` 的复合命令和改变工作目录的选项不猜。
- 推荐在提示符出现的瞬间就显示，不再等候选列表算完；用 ↑ 调出历史、接受 shell 自身建议或 Tab 补全后执行的命令同样能推断。
- 空提示符上的灰色建议不再随提示符重绘闪烁。

## 本机终端不再默认交给后台服务托管

- 本机新建的终端现在是普通的原生终端。需要「退出或崩溃后 Shell 继续运行」的用户，可在设置 → Shell → 会话恢复 打开「本机后台保活」；也可以对某个工作区使用「托管到后台」手动转为托管。远程机器不受影响，始终托管。
- 已经处于托管状态的标签保持原样，不会被强制换成新 Shell。

## 修复

- 后台会话服务启动的 Shell 缺少 `TERM` 环境变量，导致方向键无效、提示符被覆盖、命令行画成乱行、zsh-autosuggestions 的灰色建议看不见却会被 → 键接受。现在服务端总会补上 `TERM` 与 `COLORTERM`。修复只对新启动的后台服务生效；已在运行的旧服务需要停止后重新启动。
- 按住 Command 悬停链接时，下划线与手形光标不再消失；链接徽章改为紧凑样式并完整显示地址。
